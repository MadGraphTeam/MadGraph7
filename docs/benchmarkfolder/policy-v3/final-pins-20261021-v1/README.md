# Final dependency release campaign

This is a new campaign for the final NinjaRS and oneloopmaster `main` revisions
announced on 21 October 2026. It does not inherit numerical acceptance from the
previous `800a941f…` library. Exact dependency commits, Cargo closure, source
revision, archive, generated code and full runtime identities are recorded from
the successful installation and fresh exports before any numerical launch.

All work remains on `madloop_ninjars`. Generated trees, objects, executables,
compiler caches and temporary files remain below
`.benchmark-work/policy-v3/final-pins-20261021-v1`; durable report inputs live
here. Never overwrite an interrupted attempt. No pull request is authorized.

The final campaign proceeds as follows:

1. Validate the new isolated installer output, genuine binary128/256-bit rescue,
   invalid-input/error handling and upstream master-integral controls. Preserve
   the old installation, then publish the accepted new runtime with exact
   before/after inventory. Commit the numerical source and dependency closure.
2. Use `generation/regenerate.py` for eight fresh actual `bin/madgraph --plain`
   exports and clean subprocess builds. Its root-supplied `freeze.json` binds
   the committed source, all installed assets and coordinated CPUs. It preserves
   every archived original source, retained physical card and point stream.
   `generation/audit_core.py` records full runtime groups without evaluating an
   amplitude. Generation and build durations are preparation measurements.
3. Rerun representative fresh/persistent parity and forced genuine QP for every
   new runtime group. Run all eight core cases at the unchanged 100 fixed points,
   including Born, finite, single/double poles and split-order columns. Compare
   NinjaRS with the independently retained accepted CutTools/Ninja controls at
   the original tolerance. Record COLLIER results and inherited failures
   separately. The stopped old core remains incomplete historical evidence.
4. Measure original Ninja and final NinjaRS with the retained Fortran worker,
   identical full poles/stability/card/point settings and one evaluation thread.
   Collect at least seven adjacent alternating pairs on one quiet pinned CPU.
   Retain actual acceptance and rescue counts. Require every process's ratio and
   uncertainty to resolve the `<= 1.05` limit; increase repetitions when needed.
   The numerical denominator comparison must also pass. No diagnostic timing
   from a calibration is promoted to a measured repetition.
5. Rerun loop-induced `gg > h` and `gg > h h`, including threshold points,
   fresh/state/forced-rescue controls and seven paired timing repetitions. Rerun
   the two challenging 2-to-4 cases `g g > t t~ g g [virt=QCD]` and
   `u u~ > e+ e- mu+ mu- [virt=QED]`: 20 ordinary points plus the fixed rotation
   and mass/scale controls. Rerun complex masses, mixed orders, direction
   reversal, near-singular points, changed inputs and precision convergence.
6. Collect profiles from the actual final measured workers, run the MG7
   regression/install/export/statistics tests, and audit complete source/runtime
   bindings. Render and visually inspect a reproducible Typst report with all
   four backends, stability distributions, actual rescue counts, loop-induced
   and stress results, preparation costs and explicit remaining failures.

The eight processes, point seeds, real masses/zero widths, 1 TeV energies,
boosted on-shell 2-to-1 inputs and tolerances remain those in
`policy-v2/cases.json`. No stability threshold or physical contribution is
changed to obtain a speedup. The literal baseline is commit
`27147b3300f556a75661a886e92bdbe00558ee25`.

(SHA256 `590aed9f703925057cb7e1ae1f3cbd6d0527dba4cfe581ab7a4a653c42a14669`).
It contains 16 accepted 100-point calibrations bound through the explicit
new-cohort policy; parent incomplete/failed statuses are
preserved. It certifies no new-release result or final timing repetition.
The exact public selection and both historical/public metadata snapshots are
retained. Reading the complete native provenance also requires the pinned
installation's Cargo manifest, lockfile, configuration and library; native
build products are not shipped with the text measurements. Historical
calibration JSON preserves parsed numeric rows; accompanying worker logs are
contextual records rather than separately retained raw calibration streams.

seven paired full streams may require hours. New dependencies can change these
costs, so these observations are scheduling context only. Actual new-version
durations and uncertainties will be reported after measurement.
