# Optional implementation evidence in a new report dossier

The report selection may include `implementation_packages`, a map from the
roles below to `{"index": "report-relative/index.json", "sha256": "…"}`.
It is an explicit allowlist. The collector does not discover experiments or
read a running experiment. Each selected package must already be closed and
its complete index inventory must be retained and hash-verified.

| Role | Claim scope |
| --- | --- |
| `adaptive_debug`, `adaptive_release` | Observed Fortran tensor calls, genuine binary128 inputs, mapped bridge and 256/512-bit telemetry. No accepted amplitude tier or physical amplitude qualification. When both are selected they must identify distinct packages and libraries. |
| `born_backend89` | Retained backend 8/9 real-Z ordinary and fixed-QP controls; unchecked status 120 stays explicit. No CMS/stress or runtime qualification. |
| `symmetry_components` | Extracted DP/QP components, IEEE and input-word safeguards, traps and negative controls. No full-adapter or physical-amplitude claim. |
| `symmetry_ew100` | The separate v2 candidate's exact 100-point EW stream and six retained reference comparisons. Its precision counts never replace the ordinary campaign's older 66 lanes. |
| `cms_diagnostic` | Completed positive-width tensor protocol with retained refusals, IEEE observations and open acceptance items. |
| `common_input_diagnostic` | Exact synthetic effective inputs with retained finite comparator discrepancies, refusals and IEEE observations. No attribution of fault to a reducer. |
| `mass_diagnostic` | Retained nonmass input comparison and incomplete fixed-QP threshold aggregates. No checked-QP, physical-accuracy or timing acceptance. |
| `installer_promotion` | Applied strict-metadata source, test-source identities and recorded production test receipt, including its stated raw-log limitation. Only the metadata-hardening item is closed. |
| `symmetry_promotion` | Applied Fortran template, bound source-comparison receipt, and four tests: three compiled fixture methods and one Python permutation method. No new real-reducer replay or requalification of old exports. |
| `common_input_finite_audit` | Additive offline distinction between finite and aggregate pole residuals. The original diagnostic remains preserved; cause, physical accuracy and performance are unqualified. |

The implementation collector binds all package files before extracting claims.
Gzip payloads are verified as stored bytes before decoding. The runtime helper
rechecks the retained adaptive execution and Born comparisons without loading
scientific libraries or running native work. New primitive values and package
pins are included in the new dossier; only corresponding diagnostic prose is
replaced. Unselected historical claims remain associated with their original
evidence. The report build binds both collector modules as inputs.

Production promotion requires a separately selected applied-change and test
receipt: neither an isolated correction nor a successful experimental runtime
proves deployment. The optional `installer_promotion` role covers only the
strict-metadata correction. It binds the applied source/test copies, recorded
passing checks and compatibility with the existing qualified prefix. Its receipt
explicitly states that no raw pytest log was captured. `symmetry_promotion`
binds the separate applied Fortran template and recorded fixture test log;
it does not promote the adaptive bridge or change older exports. The adaptive
bridge remains experimental; production promotion still requires checked
stability, trap behavior and broader physical qualification.

This supplement never changes the main campaign, stress or performance gates;
the separately proved installer metadata-hardening item can become passed.
The optional closed provisional timing package has its own independent
contract in `PROVISIONAL-REPORT-CONTRACT.md`; it identifies the older frozen
candidate and gives descriptive shared-host observations only. Precise timing
and the per-process acceptance bound remain a TODO for Hua-Sheng locally.

Create a fresh immutable selection and dossier when selecting these proofs.
Do not edit earlier selections, dossiers, frozen report snapshots or raw data.
Canonical rendering requires the parent task's admission after the relevant
packages are sealed; adding this source support alone does not render a report.

An optional `next_campaign` selection separately pins a fresh registration's
manifest and unmeasured summary. The collector requires all eleven cases to
remain pending with zero samples and no retained attempts. It displays that
registration's source identity and local-handoff scope without importing its
rows into the older measured campaign. Missing observations are not reported as
numerical failures.
