# Formal timing scheduling, attempt 1

This source-only package has **not** launched a formal measurement. It changes
no benchmark tool, worker, numerical source, card policy, protocol or existing
schema. `process_cleanup.py` is a byte-identical copy of the reviewed numerical
supervisor helper (SHA256 `240d1067a7b7098f056f0f367097def8f374d7979c3001d249c8b1f7cb0bbd84`).

The sole child command, with the Python executable resolved by the same sourced
environment as preparation, is:

```sh
python3 -B tools/tirust_benchmark.py campaign --campaign split-dp-terminal-1 --cpu 9
```

No subset, label, chain, repetition, timeout, retry or CPU override is accepted
by this supervisor. The unchanged campaign attempts **all eight main chain
gates**, retaining each failure. Any failed/ineligible/incomplete main chain
defers the entire regression/control phase. If all eight pass, the same command
continues through 32 required existing-backend regression gates, eight
descriptive standalone-TIRust comparisons, and the three controls' six
comparisons each. Control speed ratios are descriptive. Generic core control
`status`/qualified-failure fields must not be interpreted as additional speed
requirements; the role-aware report collector owns that distinction.

The existing protocol uses seven alternating adjacent pairs, complete
100-point traversals, a two-second calibration target, and the previously
approved **0.95-second measured batch floor**. Its performance criterion is the
upper endpoint of the two-sided 95% Student-t interval on paired log ratios,
bounded by 1.05 for each required comparison. Actual durations and host load
remain in the original measurement records. This package adds no timing
outlier filter, retry, statistical rule or replacement measurement. Existing
3,600/14,400-second worker wait limits remain administrative per-wait limits,
not a total supervisor deadline.

Before admission, `preflight.py` requires the final numerical supervisor status
to pass all eleven cases with the six exact lanes (baseline CutTools and
candidate 1/6/7/8/9). It replays the unchanged warmup parser and comparison over
every retained final 100-point stream, checking the case/lane summaries,
source/build/protocol/card/point bindings, and successful post-observation
bindings. It also verifies the frozen preparation index and all 22 current
source/object/executable identities, effective compiler policies and actual
resolved runtime dependencies. The old numerical-card selections are checked
against their retained before/after records: ordinary backend changes made by
the formal controller are permitted. Physical cards and numerical code remain
fixed. Ordinary target misses remain reported by the original comparison;
they are not silently converted into a stricter acceptance threshold.

Run these stages only when separately instructed, from the repository root:

```sh
source tools/tirust_env.sh
# Prints the proposed command only; performs no preflight or workload.
python3 -B docs/benchmarkfolder/campaigns/split-dp-terminal-1/timing-qualification-1/run.py
# After all ordinary numerical results finish: read-only checks, then seals admission.
python3 -B docs/benchmarkfolder/campaigns/split-dp-terminal-1/timing-qualification-1/run.py --preflight
# Only after the root coordinator writes the separate clearance described below.
python3 -B docs/benchmarkfolder/campaigns/split-dp-terminal-1/timing-qualification-1/run.py --execute
```

`--preflight` creates `admission.json` once, without compiling or evaluating an
amplitude. It performs source hashing, `ldd`, compiler identification and
existing make dry-run flag inspection. It does not create an authorization.
The existing campaign guard may also append a newly discovered predecessor
failure to its discovery journal; these original retention safeguards remain
enabled. Thus preflight means no numerical/build workload, not zero file writes.
`--execute` repeats the same checks and requires exact admission equality.
Existing formal run directories, specification, status or console records
prevent another launch. Failure is retained without automatic rerun; a new
authorization cannot overwrite this attempt.

The **root coordinator alone** must write `quiet-window-clearance.json`, after
all owned native and compilation jobs are idle and host conditions are
acceptable. No such file is included or generated by this package. Its required
fields are:

- `authorized_by`: `/root`; `decision`: `authorized`.
- `manifest_sha256`, `source_freeze_sha256`, `admission_sha256`: exact current seals.
- `command`: the exact command array from admission; `cpu`: 9.
- `owned_native_and_compilation_jobs`: an empty array.
- `all_owned_native_and_compilation_jobs_idle`, `host_conditions_acceptable`,
  `reserve_window_until_controller_and_owned_workers_exit`: all true.
- `issued_utc`, `launch_not_after_utc`: timezone-aware ISO timestamps defining
  the allowed launch interval; they do not shorten the running campaign.
- `notes`: a nonempty factual basis for clearance, including the observed job
  and host state.

The attestation records coordinator authority; it is not an OS-level proof of
global exclusivity. Root must keep other owned compilation/native jobs paused
for the entire window, including backend 1/6/7 comparisons which do not take
the shared Rust lock. The supervisor acquires **no outer numerical flock**;
doing so would deadlock the existing child protocol. Other users' host load is
neither controlled nor silently assumed absent.

The reviewed cleanup helper defers SIGINT/SIGTERM until an owned controller
handle is recorded. It first permits cooperative Worker/ExitStack shutdown,
then can signal only observed descendant groups whose process-start/session
identities still match. Survivors block successful completion. This is an
observed-descendant guarantee, not proof about unobserved/reparented children.

Unresolved stress/scientific questions may remain open while this separately
qualified **ordinary** campaign is timed. Neither admission nor a passing
ordinary timing result qualifies the overall implementation: all records keep
`overall_goal_qualified=false`. No scientific failure is excused by this
scheduling distinction.
