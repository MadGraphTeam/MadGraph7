# Held internal-copy validation of the committed QP factor generator

Prepared only. Do not run either phase until root coordinates it. The generator revision is pinned to `f4bffc61ed67e5d083b80ff9901768d4d5779989`. The ongoing13-case generation and production sources remain unchanged.

`validate.py prepare --cpu 2` will copy the existing installed ABI3 prefix to a private directory within this namespace, verify exact file hashes, and use that private prefix in a fresh actual CLI `u u~ > z g g [virt=QCD]` standalone export with internal dependencies. There is no installer or Cargo invocation. It checks136 selected private factor calls and per-batch IEEE declarations/fresh flag capture. The output is relocated, then only this private installation copy is renamed out of reach before compiling the standalone check. The main `HEPTools/ninjars` is never hidden or changed; its original manifest is rechecked. Copied archive, module, Fortran module source, C header, ABI/link metadata must be regular files with the exact installed bytes. Original Ninja6 is expected to be unavailable in internal mode. The executable must link GNU's versioned binary128 helpers, resolve all dynamic libraries, and use no original/private NinjaRS prefix in its link recipe.

The diagnostic driver changes only `READPS` to true, uses20 calls for initialization, accepts an explicit stable-check argument, and prints every final physical/total split-order Born/Laurent row. The input is exactly the first five momentum rows of the retained100-point QCD3 stream; its full parent-stream hash is checked. The initial generated parameter card is retained, then exactly the benchmark’s zero-decay-width policy and canonical ParamCard writer are applied; the resulting card must match the retained Ninja6 fresh-development card byte-for-byte. Explicit loop-optimized output and real-mass scheme are set in the CLI. Shared numerical settings are copied from that retained measurement (including `MLStabThres=1e-9`, `COLLIERRequiredAccuracy=1e-12`), with exclusive backend8 and the explicitly chosen DP/QP/stable mode.

`validate.py run --cpu 2` requires the sole Symbolica MP slot. It runs forced DP, forced genuine QP, and automatic stability modes in separate processes, retaining cards/stdout/all rows/return codes. Expected final statuses are110,120,and218 or322 respectively. It compares all eight coefficients (physical order plus total) pairwise among modes and to the retained same-point original-Ninja6 result using the unchanged coefficient tolerance `1e-7*max(|a|,|b|)+1e-10*S`. It retains any failure and never excludes a sample. Each process is bounded to600seconds. This one-point relocation/interface check is not full-stream correctness or performance acceptance; factor fast/fallback acceptance is not instrumented. Only the runtime phase evaluates amplitudes.

Both phases refuse existing output/evidence. Failure evidence stays in place; use a new namespace for retry. Source/build/runtime hashes and the installed main prefix are verified before/after. Generator sources are frozen during preparation; the runtime phase checks exact compiled source and executable identities. CPU2 is the proposed build/control core, subject to root scheduling.
