# Source3: geometry-window source admission

This private proposal joins source2's momentum-prefix proof to the existing
source1 runtime plumbing. It changes no production source, numerical invariant,
mass, threshold, reducer, cache, or public LOOP_N ABI. Scientific dispatch still
calls the original helper through the metadata-only seam. No compiler, loader,
reducer, amplitude or performance qualification follows from these source tests.

The whole-producer `source_environment_supported` constant remains `.false.`.
Two new constants are explicitly narrower: `geometry_window_dp_source_supported`
and `geometry_window_qp_source_supported`. A typed `geometry_window_source_ok`
query admits DP only for modes1/2,width64 and QP only for modes4/5,width128.
These are source-window conditions, not runtime or complete physical gates.

Finalization reparses each bound generated precision family with source2's
unchanged `momentum_window`. It binds the full generated source inventory,
the exact parser subset, ordered batch bytes, same-kind DAG producer receipts,
route metadata, and fresh prefix/suffix result. A serialized old result alone
cannot enable a newly emitted window. Missing, changed, incomplete, unknown or
ill-typed joins emit two false constants. Hashes detect stale/mixed receipts and
support reproduction; they are not an adversarial proof of untrusted Python.

Admission requires the prefix through the last relevant W.P producer to have
complete expression-FUNCTION/CALL closure with no unqualified control effects.
The suffix must be reference-complete and have no later direct momentum,
whole-W, numeric-dummy/formal-forwarding or incompatible COMMON writes. A resolved
scalar WRITE or STOP strictly after momentum construction may retain its runtime
limitation without making the complete producer pure. A reachable unsupported
suffix function remains unknown, regardless of matching endpoint tokens. Model
initialization outside the construction window and unreachable helpers are not
silently classified pure.

The existing lifetime transformations remain byte-exact:

- Label208 invalidates DP/QP tokens and freshness for each initial/rotated point.
- Each helicity clears DP freshness before the coefficient-skip branch. Capture
  occurs before the earliest generated Born/CT producer even when that list is
  empty; FILTER_SO makes freshness false.
- Every MP caller clears DP freshness before entering the MP construction path,
  which can narrow MP momentum fields into DP W storage.
- MP outputs start invalid. Only genuine COMPUTE_INTEGRAND_IN_QP captures a QP
  token; skipped or widened-DP construction retains false freshness.
- State may serve current split-order batches but is invalidated after the
  actual terminal SO loop or amplitude-reduction terminal label. It cannot be
  inherited by a later MP_DONE/GOTO300 coefficient reuse pass.
- Each wrapper still checks GP_FRESH, an admissible unchanged environment token,
  exact route WE/PAIRING, route support and producer-kind compatibility before
  reading source-bound external slots and constructing integer-only bounds.

The new source-window query replaces only the impossible whole-producer gate in
that conjunction. It does not weaken any freshness, environment, route, or kind
condition. No state object, cached event ID or global mutable admission is added.

The remaining required boundary is compiled observation of entry→producer→use
and every negative skip/reuse/rotation/narrowing path under the actual compiler,
ABI and generated caller. Those tests must compare observed control settings,
flags, source-bound slots and bound outputs, and only then qualify a private
scientific dispatch using the already tested integer-certificate machinery.
Loop-induced/custom source families with unresolved arity/effects retain legacy
fallback. Broad physical/CMS accuracy, cached checked rescues and precise local
performance remain separate open requirements.
