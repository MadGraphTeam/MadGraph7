# General QP mass source qualification: actual EW amplitude

This package is source preparation only. No compiler, linker, loader, amplitude,
or reducer has been run by its preparation. Parent `control.py` owns any later
authorized execution, process cleanup, numerical lock, resource limits, exact
input verification and output closure. Nothing here authorizes that execution.

The proposed comparison exercises the combined general exporter, HELAS writer
and templates on all 200 retained groups of `e+ e- > t t~ a [virt=QED]`.
The seven actual helper families and three QPMASS adapter routines are emitted
through the real proposed exporter and normal Fortran writer. The actual frozen
group metadata reconstructs the HELAS amplitude objects passed to the writer;
this is not a fresh full MG CLI process generation. The generated caller uses
the proposed `CTMODE.LT.4` guard. Its DP branch is exactly the legacy actual-
argument list, and its QP branch is exactly the frozen candidate paired list.
No `_KIN` classifier or new kinematic policy is included.

**Observer ordering:** the old prototype squared QP masses before choosing a
reducer. The general helper squares them after choosing backend 8 or 9. The
`QP_M2L` observation therefore moves after the last square, inside that actual
backend guard. It never reads an uninitialized QP mass array. The patch files
bind every observer insertion. Intermediate sticky IEEE flags are recorded but
their event timing is not compared to the old prototype. Final host IEEE flags,
public return status, reduction failure messages, all mass/nonmass transport
words and all result words must match the frozen candidate oracle.

Four proposed compiles build the added helpers, added adapters, guarded caller
and narrow DP driver. Three links reuse the exact 24 frozen original object
files and unchanged archives/shared libraries, replacing only the stated caller
and/or driver objects and adding the new helper/adapter objects. Original CT
and TIRust objects have no QPMASS symbols, so they retain all legacy entrypoints.
The QP executable reuses the frozen corrected driver's object byte-for-byte.
The DP driver observes only the ordinary point and performs the same bounded
warmup sequence with that point. Its added model snapshots transfer storage
words without numerical arithmetic. It does not observe native DP transport;
zero QP group/native records are required and explicitly reported.

The six proposed executions are legacy/guarded DP on the ordinary point for
backends 8 and 9, then guarded QP on the original ordinary and threshold points
for both backends. QP compares against the frozen candidate journals, not the
old DP-squared-mass journals. Backend 9 must retain its 37 threshold native
refusals. Fixed modes do not establish independent host stability or physical
accuracy; their unchecked return codes must not be described as acceptance.
There is no timing or performance claim.

Every run directory already contains regular copies of complete historical
resources, the exact parameter card and selected point literals. Only explicit
backend/CT mode settings differ; finite computation and genuine QP integrands
remain enabled. `LoopPoleMode=0` is preserved. There are no runtime card edits
and no mutable inputs. The declared native output closure is `mass-observer.hex`,
`observer-run.log` and `param.log`; controller stream/loader logs are separate.
Any extra native output, changed input, partial journal or missing footer fails
qualification and must be retained as evidence.

`prepared.json` contains exact source/dependency hashes, build and run argv,
the inherited build environment, all runtime DSO identities and frozen oracle
hashes. Historical objects/archives are checked against their original frozen
prepared/build manifests before being bound here. The historical `ldd` map is
preserved separately: its interpreter row was produced by a different glibc
`ldd` environment. Direct loader validation must first extract PT_INTERP from
each newly linked ELF and require equality with the pinned historical PT_INTERP,
then execute that interpreter's `--list` under the runtime environment. All
ordinary SONAME/path/hash entries must match the historical map exactly; the
interpreter identity is bound independently rather than relabeling the old
observation. No loader command was executed during source preparation.

The parent build cap is 180 seconds total shared with the recording fixture,
one job on CPU 8. Each of six EW processes is capped at 120 seconds including
startup; warmup is capped at 1002 calls after its bootstrap. Failures have no
automatic retry. The offline `analyze.py --stage dp|qp|all` parser checks complete
logs/journals and exact comparisons. It deliberately does not certify the parent
controller's execution envelope; that envelope is a separate necessary gate.

An initial pure-Python preparation stopped on an object-count assertion: the
inherited recipe has 24 objects, not 25. Its generated drafts and failure note
are retained in `source-draft-1/`; correcting that assertion changed no scientific
source. No compiler or native process was started by either preparation.
