# Combined QP mass transport qualification preparation

This isolated tree composes the frozen general MP-mass source, the successful logical-IF format correction, and the caller guard. It changes no production file, installed reducer or dependency revision. The graph-based `_QPMASS_KIN` consumer is deliberately a separate implementation and is not included.

`source-manifest.json` binds the eleven composed source files to their exact parent files and indices. The source implementation retains legacy public entrypoints, sends genuine existing MP model mass values only through the paired backend8/9 QP path, and executes the exact legacy call in CTMODE<4 before any MP actual argument is evaluated. The new caller CT COMMON has the same LSCALE/CTMODE layout as the existing helper/main routines.

The proposed qualification has two complementary parts. `fixture/` uses actual generated HELAS call blocks and split-call declarations with recording helper stubs. It will compare DP argument/output/status/IEEE behavior under explicitly poisoned MP storage and separate enabled-invalid-trap cases, plus normal QP transport. The poisoned storage represents omitted valid MP initialization; genuinely uninitialized memory is undefined and is not a reproducible oracle. No claim will rest solely on the absence of a trap.

`amplitude/` uses historical EW ordinary and threshold inputs with real backend8/9 libraries. The child preparation retains its original historical49af library binding as source evidence. The aggregate manifest explicitly replaces the TIRust link inputs and runtime with a copied coherent current059bb installation: DSO eb3d67fd..., archive0c86349a..., and module d7838e75.... The public module is byte-identical to the historical module; original static NinjaRS and all other frozen generated/model/numerator objects remain unchanged. Runtime loader lists must verify the current DSO path/hash for every EW executable. The historical49af new-mass journals remain historical comparison oracles, not a claim of identical library identity.

Legacy versus guarded fixed-DP ordinary controls compare final values/status/host IEEE flags. Guarded fixed-QP observations compare against the retained MP-mass prototype, including every failed tensor; these remain unchecked fixed-mode diagnostics. General helpers square QP masses later, after library selection, so their observer records MP_M2L after that assignment. Earlier intermediate flag snapshots whose arithmetic ordering changed are not an equality oracle; the exact inputs, served tensors, final statuses and final host flags remain required checks. DP runs do not acquire fabricated QP tensor journals. The historical TIRust threshold oracle has37 refused tensors, so neither closeness nor exact reproduction qualifies its incomplete aggregate amplitude.

The concrete proposal is19 sequential compile/link commands (one job, CPU8,180s global limit),7 direct-loader listings (30s global limit, no application entry),218 caller cases (3s each,60s aggregate), four ordinary DP workers and two two-point fixed-QP workers (120s each,720s aggregate). Offline parsers gate caller→DP→QP stages. The caller fixture's positive invalid-trap control uses binary64 arithmetic; it does not independently certify binary128 signaling sensitivity. Bitwise argument/output/model comparison remains required.

Every loader/native admission takes the shared numerical lock. Waiting is outside execution caps with a separate7200s admission bound. Existing reports/outputs prevent retries. The controller uses the previously reviewed owned-process-group cleanup, retains stdout/stderr and partial outputs on failure, rejects runtime/input drift, and does not continue after a failed stage. Three parser jobs are bounded20/30/30s separately. No performance result is proposed.

No compiler, executable, loader or reducer has been launched for this combined tree. After root review, the exact commands are `python -B .tirust-build/qp-mass-general-implementation/combined-qualification/control.py verify`, then explicit `build`, then explicit `run`, from the MadGraph root after sourcing `tools/tirust_env.sh`. Source-only manifest assembly is `prepare_controller.py`; it copies/hash-checks current installation files but never invokes a loader/compiler. Previous successful compile-only checks cover the format-only parent, not this combined caller guard, numerical ABI or host stability qualification.
