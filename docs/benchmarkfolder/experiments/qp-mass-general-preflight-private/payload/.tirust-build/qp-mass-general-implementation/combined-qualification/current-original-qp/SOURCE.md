# Additive original-QP control using the current runtime

Source preparation only: no compiler, linker, loader or numerical code has run
as part of this preparation. The separate parent controller owns authorization,
the one link, exact runtime validation, cleanup and two bounded processes.
`child-prepared.json` is this scientific preparation's manifest; the parent owns
the aggregate `prepared.json` and execution envelope.

The one link is derived from the already built current-runtime guarded-QP link.
It removes only the added QPMASS helper/adapter objects, restores the frozen
original caller object and changes the output executable path. All 24 object
files, including the corrected observer driver, come from the historical
original arm. There are no new Fortran sources or compiles. The current copied
TIRust archive and `eb3d67fd…` shared library are the same inputs as the guarded
arm. NinjaRS and other libraries are unchanged. Direct-loader verification must
match the same ELF interpreter and entire resolved runtime map before execution.

Each backend's private run directory copies only the exact bound input files
from its current guarded-QP directory. Point literals, parameter cards, complete
resources, explicit backend, fixed CT mode 4, initialization mode 1, finite terms,
pole selection, QP integrand policy and cache controls are therefore identical.
No card changes occur during execution. The two processes use the ordinary and
threshold points with the same driver and warmup bound as the guarded arm.

This isolates the observed squared-mass transport change within the retained EW
amplitude. It does not test broader graph generation or Born handling. It is not
a performance benchmark, a checked-QP result or a physical accuracy gate.
The parent must first require the completed combined run and its 218 recording
cases, four DP cases and two guarded-QP cases. Proposed caps are one 30-second
link, 10 seconds total for two loader checks and two 120-second native processes,
on CPU 8 with one worker and no automatic retry.

`analyze.py` requires the strict frozen parser's complete two-point/200-group
journals and bounded completion logs. The primary comparison uses original and
guarded arms with the **same current runtime**. It demands exact group order,
point and model storage, DP squared masses, kinematic shifts, numerator
coefficients, native scale and backend/cache/check policy. It validates that each
adapter's mass entry equals the squared-mass array recorded in that arm's own
precision. MP mass arguments, QP squares, native masses, derived kinematic
matrices, tensors and final results are classified separately. Result equality
between the two mass policies is deliberately not a pass condition.

Every public/native status, refusal identifier and message, group stability
record and IEEE flag record is retained in the comparison, including differences.
Intermediate flag event timing can differ because squaring moved after backend
selection. Differences in final amplitudes, statuses or flags are evidence to
inspect, not silently counted as numerical acceptance or discarded failures.
Unknown record categories, malformed/incomplete journals, changed fixed inputs
or group order, and changes outside the permitted mass-dependent categories fail
the source-defined comparison.

Frozen `attempt2/execution-1/raw/original-8` and `original-9` journals with the
historical `49af…` runtime are secondary controls. The old candidate journals
also provide a secondary control for the guarded arm. They are never substituted
for the same-current-runtime pair. Secondary comparisons require the same mass
policy's input words to remain identical, while numerical/status/flag differences
are recorded without requiring historical result equality. The final summary
must bind the parent execution/runtime envelope separately before making any
claim about actual completed native runs.
