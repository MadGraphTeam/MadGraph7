# Adaptive physical diagnostic: one executed attempt, additive offline correction

The single admitted private replay completed both native processes. The
released adaptive bridge's exact mapped bytes were
`c5de24e6c41a90caf9e34684392d0193588522f26e6bbac646bdf74e5f151cb7`.
All 400 observed reductions were served. All 37 formerly refused same-input
reductions were served, and all four raw tensor slots, contracted group
results and stability values of the other 363 calls remained bitwise
identical. Genuine point/model/MP-coordinate/native integral input bits and
cache/check policy values agree. Born flat indices 1 and 5 agree at both
points. The old console has 74 W03 omission warnings; the new console has none.

This establishes a narrowly scoped diagnostic result, **not physical accuracy,
checked stability, working-tier provenance, or performance qualification**.
The fixed CTModeRun=4 public status remains unchecked. Per-call working
precision was not observed; a successful call is not labeled a 512-bit call.
No independent numerical truth is assigned to outputs of previously refused
calls. Same-input independent reduction or precision-convergence evidence
remains required. The separate Fortran transport qualification retains its
own scope. This package does not alter COLLIER or its reported cache bug.

The original controller returned 1 after the native work because its offline
analyzer classified `FPE_QP_BEGIN` as a physical point input. Its value changes
from true to false at both points. The original execution record still says
`complete: false`; the original proposal, source, failed analysis, outputs,
and run record remain unchanged. There was **no native retry**.

`FPE_QP_BEGIN` is the existing MadLoop software reduction-failure latch from
`COMMON/ML5_0_FPE_IN_REDUCTION`. It records prior bootstrap/warmup history,
including earlier tensor refusals; it is not a mass, momentum, coupling,
numerator, cache policy, or other physical input. It is distinct from hardware
IEEE exception flags, which the journal also records. Source evidence is
retained under the `diagnosis-source/` payload keys: the snapshot reads the
latch before the current evaluation, and the adapter sets it on an unstable
reduction. The original true state was inherited from warmup containing the
threshold point. A false state does not establish checked stability.

The additive offline successor changes only that classification and adds
explicit Born-output checks. All four `FPE_DP/QP_BEGIN/END` observations are
retained with old/new values; the result records four actual differences:
QP begin and end at both points, true to false. Every other point/model input
constraint remains in place, as do all native input and served-output checks.
The unified patch, original failed analysis, corrected offline analysis and
fourteen synthetic tests (including separate Born-slot subtests) are retained.
Point 1 preserves all amplitude words. Point 2 preserves Born and changes its
finite/pole sums after the formerly omitted contributions are included; those
changed sums have no truth qualification here.

The executed scope was one unchanged copied executable, the same eight input
files and a full 15-object runtime closure. Fourteen DSOs were copied and the
