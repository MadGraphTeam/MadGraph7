## Proposed behavior

1. **Gram normalization:** store the existing binary64 square-root denominator once; return `None` if its magnitude bits are zero, before division. With IEEE masked arithmetic the old result was already `None` for either denominator zero sign and any numerator class: the quotient cannot be finite. All nonzero denominator arithmetic and final selection remain literal old code, including infinite denominators. This is a method-choice control path. It does not make a singular Gram successful, loosen a guard, suppress tiny nonzero overflow, or protect earlier normalization arithmetic. IEEE flag/trap effects intentionally change for the bypassed division; full floating-environment equivalence is not claimed.

2. **Dilog term estimator:** optional `checked-dilog-rounding`, disabled by default, replaces only the ratio by positive infinity when `0 < modulus.to_bits() <= 0x0030000000000000` and a **fresh** checked probe returns true. This interval is positive binary64 modulus ≤`2^-1020`. The numerator `4*PI*PI` is greater than32, so the exact quotient exceeds `2^1025`, above the nearest-overflow midpoint. Under nearest binary64 with FTZ/DAZ clear, the old ratio therefore rounds to positive infinity and the unchanged remaining expression produces one coefficient before the existing table cap, for every u32 bit count. No finite, dilog, branch, coefficient, Horner, or precision expression is otherwise changed. The existing caller's exact-zero bypass still uses zero coefficients. Negative, either zero sign, nonfinite, larger or unknown cases retain the literal old division.

Round-down/toward-zero overflow can yield binary64 MAX and a positive finite term-count quotient, changing the old count to at least two. They must use the old path. Suppression of the old overflow/inexact status effects is intentional. This is a conditional preservation of the **old masked coefficient count**, not a new approximation or an error certificate. The actual trapped modulus was not captured; the proposal may not cover it.

3. **Safe callback:** oneloopmaster retains `#![forbid(unsafe_code)]` and gains a feature-gated safe scoped `fn() -> bool` callback using thread-local `Cell<Option<fn() -> bool>>`. No callback is installed by default. RAII restores the previous pointer on normal return and Rust unwinding, including nested scopes and callback panics. No borrow remains while invoking host code. The hook is temporarily removed during its own invocation, so reentry sees no hook and follows old arithmetic. The callback contract forbids changes to the floating environment and scientific-kernel execution. No cross-thread propagation occurs.

4. **Private bridge plumbing:** the existing unsafe-capable bridge wraps its existing panic boundary's action in the scoped callback only when explicitly feature-enabled. At every eligible estimator visit the callback invokes the existing C token probe, which reads MXCSR and x87 control words without writes. It requires the expected marker, nearest rounding, no FTZ/DAZ, and the prior conservative x87 precision contract; unknown architectures/compilers return zero and use the old path. Exception masks may be enabled or disabled, and sticky flags are excluded from the token. The probe is not a token captured once at the C boundary. The bridge's error/status branches, cache/store namespaces, event lifecycle, failure clearing, eligible adaptive rescue predicate, and 256/512 precision constants are textually unchanged.
