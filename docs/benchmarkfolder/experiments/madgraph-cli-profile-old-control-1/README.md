# Closed stock MadGraph profile control

Actual CLI `check profile` commands compare backend8 NinjaRS and backend9 TIRust for QCD `u u~ > z`. Both completed with the same signed TIRust installation, source cafb35d7, full finite plus UV/IR mode0 and all configured helicities. The second command reuses a private clone of the first export. Both owned cleanups have no survivors; source and shared inputs remain unchanged.

The table retains stock fixed-DP FULL and SKIP timings. The retained polarized FULL result is zero for the first configured helicity in both backends; that selection was not qualified as contributing, so only the all-helicity timings are used for comparison. FULL−SKIP is an estimated reduction time. The two commands choose different short batch lengths; their single-run ratio is descriptive, without a paired interval or performance acceptance. Stock timing has no per-point return-code/precision stream. Separate ten-point stability samples are within-backend direction/rotation spreads, not errors against an independent reference. The normal stability samples do not retain every original momentum.

NinjaRS records a fresh two-point filter-free initialization. TIRust reuses the generated export and has no separate Initialization measurement (null, never zero); its estimate and boot stages are retained. These timings belong to the pre-adaptive signed S DSO85ee and do not qualify a future bridge or Fortran change.

`summary.json`, `timings.csv` and stability CSVs derive only from retained stock metadata/pickles. The full CLI/profile/stability logs, commands, cards, flags, stage driver/matrix snapshots and owned terminal receipts are retained. `path-bindings.json` maps original absolute source-snapshot observations to packet-relative copies; source and runtime library identities remain unchanged. Existing dynamic/static libraries are identified by hashes rather than repackaged. Source commit and reproduction commands are in preparation/. A rerun must use a new namespace and explicitly rebind local tools and dependency prefixes.
