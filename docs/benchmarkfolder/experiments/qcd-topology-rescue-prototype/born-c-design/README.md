# Actual-C Born handoff: source-only design

This is a private coordinate-policy derivation from the frozen revision-2 Born fallback and its frozen observed host. It prepares an exact patch, not a compiled or numerically qualified implementation. The parent owns integration with topology-gated matrix construction. Original, promoted-B, Born-consistency and observer evidence remain unchanged.

The exported pure functions in `derive.py` are `transform_wrapper(text)` and `transform_host(text)`. The latter accepts the bare revision-2 host or its observed copy, uses unique invariant anchors, and preserves the complete actual `SET_MP_PS` routine and existing QOBS hooks byte for byte. `derive_sources()` binds the frozen input hashes and returns the transformed source strings without writing them. The retained `born-c-handoff.patch` uses the observed host. Run `PYTHONDONTWRITEBYTECODE=1 python3 docs/benchmarkfolder/experiments/qcd-topology-rescue-prototype/born-c-design/derive.py` from the MadGraph root to reproduce and verify the patch and source bindings. Preparation uses `--prepare` and refuses overwrite.

## Ordering and current-call ownership

The revision-2 host calls its Born wrapper at `loop_matrix.f:809`, publishes `ANS(0,:)` at 828 and computes `REF` at 834. It subsequently resets `MP_DONE`, `MP_DONE_ONCE`, and the saved local `MP_PS_SET` at 839–841. Simply calling `SET_MP_PS` inside the Born wrapper would therefore be insufficient: the later lazy preparation at 997–1000 would execute again. In addition, the host's DP preparation at 940–958 invokes `IMPROVE_PS_POINT_PRECISION`, which itself promotes, repairs in MP, and rounds back. Both duplicate sites must be bypassed for a literal single-preparation claim.

The exact proposed order is:

1. The new private wrapper `ML5_0_BORN_WITH_C_RESCUE` resets its output `C_READY` to false, then retains the original IEEE snapshot, DP Born call, finite guard and ordinary early return. It does not prepare, inspect or initialize any C array on the ordinary path.
2. Only after the original DP Born fails, preserve the existing helicity-cache invalidation and restore-entry/clear-flags rescue interval. Call the actual `ML5_0_SET_MP_PS(P_USER)` once inside this interval. Its output `MP_PS` is copied exactly to binary128 C. The existing point-scope observer hooks capture the input promotion, output C and initial MP_P.
3. Reject nonfinite C or invalid/divide-by-zero/overflow from this preparation. Produce and check `PC=REAL(C,8)` inside the same interval. Compute the existing QP Born aggregate on C, retain all its averaging and selection rules, convert its output to DP, and apply the original final finiteness/flag checks and entry-status restore plus flag merge. `C_READY` becomes true only on current-call success. It is a data handoff, not a checked-amplitude certificate.
4. The host publishes the rescued Born and computes `REF` in their original locations. After its normal reset block, a successful C handoff assigns `MP_PS=C`, `MP_P=C`, and `MP_PS_SET=.TRUE.`. `MP_DONE` and `MP_DONE_ONCE` remain false: preparing coordinates does not compute loop numerators or prove QP work.
5. For this rare path only, use the checked PC for `PS` and hence the host DP trial P, and skip the subsequent DP repair. Keep the full C in the MP COMMON; never reconstruct it from PC. The existing lazy QP setter is skipped by `MP_PS_SET`. Ordinary calls retain their original P_USER copy, DP repair condition and lazy QP preparation.
6. Existing checked-QP dispatch, cache resets, direction tests, rotations and certificate conditions remain. The certificate additionally requires the current `BORN_C_READY`. Existing MP rotations derive `MP_P` from fixed `MP_PS` and invalidate `MP_DONE`, including when restoring rotation zero; these calls must not be removed or followed by another repair.

Here “one preparation” means one `SET_MP_PS` call on a rescued point, with no second host DP/MP preparation. The called repair routine may itself attempt its existing alternative method. `SET_MP_PS` has no success output and can retain its input after an internal repair failure. Thus C means its actual returned coordinates; neither a finite C nor `C_READY` proves exact shell restoration, conservation, or a valid amplitude.

## IEEE state, status and normalization

No halting mode is changed. An enabled trap can still stop the original DP evaluation before a fallback exists. Repair, its DP trial conversion, QP Born arithmetic and Born output conversion all occur inside the existing rare rescue flag interval. New flags from that entire interval are merged with the wrapper's entry flags; there is no blanket status restoration around later loop arithmetic. Preparation failures follow the existing early host rejection before filter-learning counters advance, with H=4/T=2/U=0, accuracy one and nonfinite output. Existing rotation backups and cache cleanup remain.

`BORN_QP_CHECKED` still resets every invocation; only the actual checked-QP accuracy branch can set it. `BORN_C_READY` cannot promote H1/unchecked output, stale acceptance state, or a loop reduction with a failure flag. The revised wrapper leaves the entire Born aggregate and kernels byte-identical, including split orders, color denominator 72, helicity/polarization/flavor selections and averaging. No caller G, MU_R, model parameter or loop normalization constant is changed. The host LSCALE expression remains in place and consumes its DP trial coordinates. For the rare C path those coordinates are explicitly PC, including when the original DP repair would have been disabled; this is an intentional input-policy change for rejected DP controls, not a claim of original-input amplitude equivalence.

The actual QP integrand flags must be true in the private experiment. Otherwise `MP_COMPUTE_LOOP_COEFS` can evaluate the numerator on rounded DP coordinates and merely promote its coefficients. A prepared C alone does not establish a genuine QP numerator. Bind this configuration and retain raw `CONTEXT_MP_PS`/`CONTEXT_MP_P` records for every reducer call. The existing point-scope `POINT_MP_AFTER` record identifies the exact C passed to the Born aggregate; rotations are separately derived from that fixed C. The ordinary–stress–ordinary sequence and distinct original/B controls are required to expose stale state.

## Deliberate remaining limitation

The QP Born continues to use exact promotions of DP mass/coupling parameters, exactly as in the frozen B control. The actual QP loop updates and uses its MP parameter representation. This experiment aligns the coordinate set; it does not resolve parameter-precision equality, change the external/internal mass convention, or establish general consistency of a same-effective-input independent reference. Those differences must be measured and stated before any acceptance claim. The B control remains valuable because changing parameter precision at the same time would obscure the isolated coordinate effect.

No compiler, reducer, phase-space repair, Born arithmetic or native validation was executed while preparing this design. Future qualification must check exact C provenance, one preparation per rescued point, original ordinary coefficients/status/flags, enabled traps and directed rounding, repair and conversion refusal, current-call certificate behavior, genuine QP integrand execution, all finite/pole modes, and agreement with independent references at an explicitly shared coordinate and parameter prescription.
