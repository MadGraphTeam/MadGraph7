# Private QCD topology and Born-coordinate prototype

This package prepares source for the retained `u u~ > z g g [virt=QCD]` ordinary/stress/ordinary stream. It does not modify production, generate a new physical point, compile, link, run a reducer or change the frozen campaign. Every proposed native process requires separate approval after source review. The original Born NaN, promoted-B fallback and both observed code-420 rejections remain immutable controls.

There are two independently selectable changes: gate the existing QP invariant-clamping branches by static topology, and compute a rescued Born on the actual C coordinates prepared for the QP loop. `arms.json` binds four source combinations:

| Arm | QP invariant policy | Rescued Born coordinates |
|---|---|---|
| `original-b` | Original | Exact promotion B; existing frozen observer control |
| `topology-b` | Certified single/complement gates | B; deliberately retains the coordinate mismatch as a causal control |
| `original-c` | Original | Actual existing `SET_MP_PS` output C |
| `topology-c` | Certified single/complement gates | C |

The loop still uses the existing C preparation and its subsequent rotations. All arms keep the old model-parameter policy: the rare QP Born promotes DP parameters, while the actual QP numerator uses its existing MP parameter representation. Aligning coordinates does not establish equality of those parameter prescriptions or independent numerical truth.

## Static topology source

`prepare_topology.py` first replays the frozen source proof of all 35 DP/MP HELAS wavefunction producers, their exact DHELAS momentum rules, 116 emitted reduction calls and corner `PAIRING` partitions. It then replays the separate integer CT4/CT5 routing proof. No process-point values are used. This private retained-export prototype obtains its graph from the audited generated source DAG; a general production implementation would instead derive equivalent metadata directly from HELAS objects during export, as described in the separate classification proposal.

The generated table covers 477 unordered pairs per direction. CT4 has 146 literal direct singles, 96 conservation complements and 235 composites; CT5 has 216, 26 and 235, respectively. All five external legs are on shell in this exact generation card. The table distinguishes direct versus complement by the sign of the stored external-leg number. Its zero class means composite or unknown, with diagonal entries also zero. Full integer vectors and witnesses remain in `table-metadata.json`; the numerical routine uses only a bounded integer lookup.

Only the generated QP8/9 call sites select the new private entry points: seven calls per backend pass their actual `LOOPNUM` and `CTMODE` explicitly. Existing DP routines, public diagnostic entry points and their call paths remain unchanged. The new classified builder has no identity COMMON and never derives its group from a previous call. Native wrapper numerator COMMON blocks retain their original role; the actual generated call establishes their ID immediately before dispatch. Source review must verify this association for all fourteen rewritten sites.

The new helper returns zero for an unknown group, wrong denominator count, invalid pair or unsupported mode. That means retaining computed `DIFFSQ`, without any clamp. Such a context is not silently qualified: any unknown actual replay context invalidates the experiment's interpretation. The original public/legacy diagnostics remain a separately documented unclassified path and are not used by this prototype. General unknown callers, ungrouped exports, other processes and other backends are outside this narrow source proof.

The private QP builder copies the original observed helper and wraps each of its three existing threshold branches in the same eligibility guard. No threshold, mass, `DIFFSQ` expression, S construction, summation order or retained branch body changes. The energy reference and its observer record are still computed for every pair outside the guard, so the frozen decoder can validate the full original trace schema. The prototype applies the same matrix rule to QP NinjaRS and TIRust; their working precision and stability gates remain unchanged.

This initial gate is a QCD experiment, not the general massive/complex policy. A certified massive singleton still executes the historical mass-comparison branches; the broader proposal's explicit external-mass target and representation contract are not implemented here. The old common builder, DP code, Ninja/CutTools/COLLIER paths and all installed libraries remain unchanged.

## C-coordinate handoff

`born-c-design/` contains the independently reviewed source transformation and its exact patch. Only after a failed DP Born, the new wrapper calls the actual historical `SET_MP_PS` inside the existing checked rare-rescue IEEE interval. Its exact binary128 output is C; a checked DP conversion PC is retained for the host's rejected DP trials. The host adopts C after its ordinary initialization resets and skips both subsequent DP and lazy-QP repair sites for that rescued call. Preparing C never sets `MP_DONE` or supplies a checked-QP certificate. Normal finite-DP calls follow the original arithmetic and repair path.

The existing `SET_MP_PS` observer hooks record exact promoted input and returned C. All QP calls record `CONTEXT_MP_PS`/`CONTEXT_MP_P`, permitting an exact handoff and rotation audit. C may equal the unrepaired input if the existing repair declines; a finite C is not proof of successful repair. No caller trap is disabled, no later loop arithmetic is enclosed by a status restore, and invalid preparation/Born/conversion still rejects before filter learning. The checked current-call certificate and final host rejection remain mandatory.

The C arm intentionally changes the effective coordinate policy on the previously rejected Born path. In particular, its PC is used for DP trials even if a different card would disable ordinary DP repair. The retained experiment's card has `ImprovePSPoint=2`. No unchanged-Cartesian-input acceptance is claimed. The B arm, C arm and original physical input record remain separately identifiable.

## Proposed build and replay protocol

The future builder should derive its exact ordered link and flags from the pinned successful observer `attempt1/build.json`, replace only the declared private source objects and add `shell_classes.o` for topology arms. Reuse unchanged observer, model, HELAS and library objects by verified hash. Compile into a new ignored work directory with an isolated module destination and the original compiler/flags. Never replace the historical executable, 49af TIRust DSO, installed prefixes or any campaign artifact. Retain every command, compile failure and pre/post source, object, archive and runtime-library hash; no automatic retry.

The source-arm table is not permission to run eight processes. After review, select a bounded sequence explicitly. Each approved backend/arm process uses CPU11, one thread, the shared `.tirust-build/numerical-tests.lock`, a hard 180-second wall limit and exactly ordinary/stress/ordinary. Reuse the original point file, parameter card, numerical card, resource files and automatic stability policy byte for byte: backend8 or9, CTModeRun=-1, MLStabThres=1e-6, OSThres=1e-8, ImprovePSPoint=2, full finite output and genuine QP integrand construction. No smaller threshold, extra working precision, repaired replacement input stream or unchecked CT4 override is allowed.

Required checks before interpretation:

1. Verify every frozen input and new source hash before compile and replay, exact ordered object/library substitutions, actual loaded DSO path/hash, and unchanged protected files afterward. The historical `original-b` control must retain its exact six amplitude rows, flags, health and code420 stress failure if replayed.
2. Require zero observer faults and successful flush acknowledgements; decode every raw payload and call stage with the unchanged strict decoder. Require original ordinary coefficients/status/IEEE flags and ordinary-repeat identity. A timeout or compiler/native failure is retained and ends that attempt.
3. Confirm every observed classified call uses a known group, matching denominator count and actual CT4/5 direction. Compare numerator, ordered shifts, masses, scale and all nonmatrix inputs with its matched control. In the topology-only B arm these must agree bit for bit. Every composite final S entry must equal its initial unmodified S entry bit for bit; eligible singleton/complement branch behavior must match the control. Native distances still use the existing S-plus-masses reconstruction, whose finite-precision rounding must be recorded rather than assumed to reproduce `DIFFSQ` exactly. Check whether each targeted native distance remains nonzero and recompute both supplied and Cartesian Gram matrices offline.
4. In C arms require exactly one observed setter triplet on each rescued point, no new preparation on ordinary calls, and exact equality between returned C, the Born source and each unrotated QP context. Check rotation zero restoration separately if reached. Preserve full original/B/C coordinate and parameter records, exact shell/composite residuals and Born normalization. A change in MP parameters or repeated repair invalidates the intended isolated comparison.
5. Record all requested native successes/refusals, numerator/output finiteness, final checked-host status and current-call certificate. A finite Born or finite subset sum is insufficient. No H1/unchecked result, stale H2/H3, failed native tensor or code420 result becomes an acceptance. Analytic Born-derived poles and cross-backend comparisons are diagnostics until their effective-coordinate and parameter contracts agree.
6. No formal runtime claim is made. If a later production proposal becomes justified, ordinary-path cost and all five backends/process multiplicities require a fresh qualified campaign under the original 5% gate. This source experiment does not modify that campaign.

The source preparation scripts are one-shot and refuse to overwrite their products. `verify.py` is a pure-Python source verifier; it does not compile or execute numerical code. The portable index binds the source variants, derivations, inputs and protocol. Any required source correction before a future native attempt must be explicit and separately bound.
