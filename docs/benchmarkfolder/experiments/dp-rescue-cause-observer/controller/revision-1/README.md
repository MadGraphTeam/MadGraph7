# Private six-arm controller source

This directory adds a controller beside the frozen 44-file observer proposal. It does not alter that proposal, its index, or its successful metadata snapshot. Build and native execution are currently unauthorized. A later root message identifying the reviewed controller/build hashes and resources is sufficient clearance; this diagnostic does not require a new authorization file or the formal timing protocol's quiet-window file. The explicit stage commands below never grant themselves permission.

The frozen proposal index is `b0b0af81739be886420450459eeed94a839c71e8aeef22b17c79d3b510c2cd1b`. Its earlier prose saying the protocol helper had not executed describes the pre-snapshot proposal. `protocol.py` subsequently ran once in metadata-only mode and produced `preparation/source-1/snapshot.json`, SHA-256 `2aa5e87ead00c163d0f987dbef257654a8a22ec748f7d3f71be68aeaa64e7759`. No analyzer tests, compilation, or native execution were performed as part of that preparation.

The frozen design's instruction to never parse the words as floating point concerns raw transport and parity, which remain exact integer/hex operations. The frozen analyzer also decodes a copy of selected binary64 words offline for threshold and nonfinite classifications while preserving every raw word. This derived classification changes no numerical input or worker behavior.

`run.py` provides three explicit stages:

- `prepare` reads and verifies the frozen proposal, snapshot, generated sources, original numerical objects, cards, points, and dependencies, then prints metadata. It does not write an attempt, run a compiler, or start an amplitude.
- `build` verifies the supplied reviewed controller, builder, and build-plan hashes and replaces itself with the separately reviewed `build.py --build` invocation. The plan binds this controller's cleanup implementation and the native input/environment inventory; the builder reconstructs its frozen compilation environment. That builder owns compile/link provenance and child cleanup. This stage acquires no numerical lock and never invokes `execute`.
- `execute` consumes an existing complete build manifest with an explicit SHA-256. It never compiles or repairs an input. It checks the frozen original and private source/object identities, including the exact four permitted observed replacements and the original arm's common-driver replacement. Observer-disabled and observer-enabled runs use the same executable and DSO.

The proposed resource budget is CPU 11, one numerical thread, 600 seconds per arm, and 3,900 seconds for the complete sequence after lock admission, including input copies, mapping reads, analysis, and provenance checks. The sequence is QCD original/disabled/enabled followed by EW original/disabled/enabled: six sequential workers, one attempt, zero automatic retries. Retained full-100 initialization took approximately 73 seconds for QCD and 102 seconds for EW; these historical values inform only the administrative cap and are not an observer timing prediction. Output limits are 64 MiB stdout, 512 MiB native journal, 2 MiB public/warmup logs, and 64 KiB FIFO protocol per arm. Exceeding any limit fails the attempt.

Execution acquires `.tirust-build/numerical-tests.lock` nonblocking before creating the attempt or starting its budget. A busy lock starts no process, consumes no attempt, and returns 75. All six workers and their validation share that lock. One fresh `controller-native/attempt1` directory is allowed under the build label; an existing directory, including one from a failed attempt, is refused.

Each arm receives fresh regular-file copies of the exact 100-point stream and metadata, parameter card, and initial MadLoop resources. `Cards/param_card.dat` and `Cards/ident_card.dat` preserve the generated reader's fallback lookup; there is no run-root parameter card. The initial `MadLoop5_resources` copies retain their original bytes. No production or registered input is changed. The original `configure()` reset policy is preserved by excluding `*HelFilter.dat` and `*LoopFilter.dat` from the new private copy and requiring none before startup. Every arm runs the full original initialization. The worker may internally attempt more calls, but this controller accepts only bootstrap call 0 followed by calls 1–100 visiting points 1–100. A later READY or different warmup sequence fails; calls are never pruned.

The only interactive worker command is `STOP 1 0`, sent after the expected READY and successful live mapping capture. No RUN command or timing loop is sent. The controller retains stdout, every FIFO byte, warmup, public/native logs, runtime maps, command/environment, input hashes, and exit/cleanup status. It requires BYE and exit 0. At READY, `/proc/PID/maps` must contain exactly the declared runtime ELF closure plus the executable, with exactly one selected `libmadloop_tirust.so`; both original and observer DSOs in one process fail. Every mapped ELF is hashed, each task's CPU 11 affinity is checked, and task IDs and actual mapping text are saved before STOP. Thread-limit variables are fixed at one; a runtime pool's main thread and worker are not conflated with its computational thread limit. A dependency listing alone cannot satisfy this check. Native context pointers are never compared between processes.

Cleanup is an adaptation of the reviewed `qcd-topology-rescue-higher-precision-runner2/supervise.py` WNOWAIT/deferred-signal ownership algorithm, bound at SHA-256 `ed25a9fc96e2faf2b545a9bf70a91b34315c01e534a6ebe68d7520ec2171aa42`. The earlier campaign `OwnedChild` lineage helper is also bound at `240d1067a7b7098f056f0f367097def8f374d7979c3001d249c8b1f7cb0bbd84` as review context. This FIFO-aware implementation does not claim byte-identical reuse. All protocol reads, command sends, polls, and mapping work use one arm deadline bounded by the total deadline. The child leader remains unreaped while owned; timeout, interruption, protocol failure, or any other exception kills its owned group and reaps it before returning to lock cleanup. Normal exit also cleans any surviving group members while the leader identity is still reserved. The final SIGKILL/reap is mandatory cleanup, not extra numerical work. Failure-record errors do not replace the original exception.

Each arm's output inventory recursively hashes retained regular files, including generated MadLoop filters and resource files; it excludes the FIFO, scratch `tmp` tree, and execution metadata itself. The original copied cards and resources must also retain their input hashes.

Only after all six arms have valid loaded-runtime evidence does the controller import the frozen, hash-checked analyzer. It preserves the analyzer report and separately records runtime provenance, exact numerical parity, and protected-input checks. Cause observations still require review; no performance or physics acceptance is asserted. The analyzer remains an unexecuted source proposal until such a separately cleared run actually happens.
