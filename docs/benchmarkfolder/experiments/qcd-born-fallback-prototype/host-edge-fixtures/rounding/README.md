This is an IEEE policy fixture for the actual revision 2 `ML5_0_BORN_WITH_RESCUE` wrapper. It uses explicit recording DP/QP stubs, so it establishes no physical amplitude, reducer accuracy, pole normalization, or performance result. It does not change the prototype or production sources.

`wrapper-used.f` is a byte-identical copy of `born_rescue.f`, SHA256 `be514aaffe9e478ce86bbfe1d83f6fdc7f08ff249b66898a7aba4a440787cfb0`, checked against the retained revision 2 preparation, SHA256 `e4f6235e7c7d3d337c567a0acd248cfa49daaaa4d265f842f4ebf5a54a81602f`. The Fortran driver records exact momentum transport, including negative zero, and calls that wrapper through its original signature.

The completed corpus is in `run-3/`. Both `-O0` and `-O3` passed 128 cases: four supported rounding modes (nearest, toward zero, upward, downward), four actions, four combinations of preexisting underflow/inexact flags, and two trap policies (all disabled, or divide-by-zero enabled). Ties-away was queried and reported unsupported for both DP and QP. All compiler and executable subprocesses were pinned to CPU 11. No reducer or model library was linked.

The actions cover an ordinary finite DP return, successful forced QP rescue, nonfinite QP rejection, and rejection of finite QP values that overflow during DP conversion. The successful rescue returns positive and negative exact QP midpoints; expected DP bit patterns distinguish the rounding modes. The overflow case checks rejection even when directed rounding returns the largest finite DP value. Assertions also check untouched input bits, ordinary signed-zero bits, entry/exit rounding and halting modes, exact sticky-flag unions, wrapper counters, and helicity-state cleanup.

Trap settings are established before entry flags are seeded. Both are captured before the call and immediately after return, before any flag clearing, halting setter, assertion arithmetic, or formatted output. Thus fixture cleanup cannot erase the state being tested. The enabled divide-by-zero trap is not deliberately raised here; this fixture checks its preservation, not trap delivery.

This is a limitation of that negative control on this compiler; it provides no evidence that the explicit restore is unnecessary on other compilers.
