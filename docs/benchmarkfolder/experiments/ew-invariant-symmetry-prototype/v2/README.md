# Private invariant symmetry proposal, revision 2

This is an additive source proposal. It has not been compiled or evaluated. Production, the registered numerical campaign, the first proposal, its successful build, and its failed component qualification remain unchanged.

The first proposal's `IEEE_IS_FINITE` scan changed local signaling-NaN behavior. In the retained recording-only corpus, each of four configurations had 120 IEEE-state differences among 1,344 original/candidate pairs; 32 invalid-trap pairs returned normally in the original direct-matrix control and trapped in the candidate. All matrix-policy checks passed. The 16 agreeing inexact-trap pairs both trapped, so they establish no returned-value equivalence. These are extracted-component observations, not a full-adapter or physical-amplitude conclusion.

Revision 2 replaces only the added floating-point finiteness predicate with integer exponent classification. `TRANSFER` copies each DP value to one `INTEGER(C_INT64_T)` and each QP value to one `INTEGER(SELECTED_INT_KIND(33))` in a one-dimensional automatic array. Integer masks select the 11-bit binary64 or 15-bit binary128 exponent. Any all-ones exponent prevents the entire mirroring block; NaNs and infinities therefore reach the unchanged later validation with their original bits. The added block performs no floating predicate or comparison on those entries.

The scalar integer views avoid selecting a high word from a two-word binary128 representation. This remains a qualified GNU IEEE-layout assumption, not a portable promise for arbitrary real or integer representations. Compile-time constant assertions require matching real/integer storage widths of 64/128 bits, radix 2, significand precision 53/113, and the corresponding minimum/maximum exponents. The existing build already uses GNU's binary128 QP ABI. Unsupported integer kinds or formats must fail compilation; they are not silently coerced.

Once every entry is finite, the upper-triangle selection and floating equality rule are exactly those of revision 1: copy an upper entry to its lower partner only when they compare unequal. Upper and diagonal words remain untouched. Already equal values, including opposite signed zeros, retain all original bytes. The shared on-shell helper, both complete reconstruction loops, masses, shifts, renormalization scale, cache controls, precision, and strict Rust validation are unchanged. Removing the two declaration blocks and the two executable insertions recovers the original generated adapter byte for byte.

`prepare.py` verifies this deterministic derivation by default. `derivation.patch` compares with the original adapter; `v1-to-v2.patch` isolates the revision from the rejected first proposal. The whole integer array is temporary per call; this is not a cache or a performance optimization claim.

`fortran-fixtures/` is a separately indexed proposal for the exact same driver cases, raw-word analyzer, rounding/flag modes, traps, and negative controls. Only the extracted candidate declarations/classification block and the necessary guard-removal mutation change. Passing that corpus would qualify the tested components only. Newly admitted real invariant matrices still need the independent host stability tests and reference comparisons.

`build-proposal/` retains the reviewed single-object build workflow with only revision paths, schema labels, and the candidate hash changed. A future invocation would compile one adapter, relink it with all other frozen EW n3 objects and flags unchanged, and obtain one bounded dependency listing. It would not run a reducer or an amplitude. Its separate source and plan hashes require explicit admission before execution. Subsequent physical testing must retain all 100 points, all coefficient values and ordinary-target misses, and actual accepted DP/QP usage; removing an input-validation error is not itself numerical acceptance.
