# Proposed compiled component fixture

This append-only subfolder is source preparation, not a test result. No compiler, generated executable, reducer, model initialization, or amplitude has been run. The parent ten-payload proposal and its index remain unchanged. The separate earlier Python binary64 witness remains synthetic.

`shared-kinematics.f` consists of two exact byte slices from the registered EW n3 generated `CT_interface.f`: its DP and QP `BUILD_KINEMATIC_MATRIX` routines. `MadLoopParams.inc` is an exact copy of that export's include. `source-inputs.json` records the original full-file hash, slice offsets/hashes and include hash. A tiny setter uses that same include to initialize `OSThres=1e-8`; none of the shared helper's arithmetic or on-shell branches is rewritten.

`prepare.py` derives the original and candidate wrappers directly from the frozen generated adapters. Each reconstruction wrapper contains the exact shared-helper call and following invariant-reconstruction loops, with the candidate's exact insertion in the candidate wrapper. A second wrapper isolates just that insertion for direct matrix edge cases. Wrapper declarations provide the same real/complex kinds. The frozen standalone declarations are fixture scaffolding; this is not a compilation of the entire adapter or its MTIRUST transport. Running `prepare.py` without arguments only compares the derived sources with the retained files.

The driver is compiled separately for binary64 and binary128. Its six helper cases are the source-derived unequal-mass example, exact massive on-shell, exact massless on-shell, complex masses with negative widths, and points just inside/outside the existing massive threshold. Direct matrix cases cover symmetric finite entries, opposite signed zeros, finite asymmetry, lower-only infinity/quiet NaN, a nonfinite diagonal plus a separate finite asymmetric pair, and upper/lower signaling NaNs. Sizes are 1, 2, 3 and 6. QP helper masses use promoted DP squared values, matching the input kind of this adapter. These are synthetic component inputs, not captured physical calls.

For every supported rounding mode, the normal corpus repeats with no entry flags and with each of the five standard IEEE flags set separately, with traps disabled. Each original/candidate pair records all caller input words, the initial/output matrix words, and five flags, five halting modes and rounding mode around the component call. The entry-state write and flush occur after the entry snapshot and before invocation, so their effects belong to this measured boundary. A stub classifies only whole-matrix finiteness and exact symmetry after the post-call state is recorded. Its status is checked independently from integer IEEE encodings; it performs no reduction. The driver uses only integer output formatting. Any flag effect of the observation code itself remains part of this fixture and is not a full-amplitude observation-neutrality proof.

Three isolated trap probes cover upper and lower signaling NaNs with invalid trapping, plus the unequal-mass helper with inexact trapping, under each supported rounding mode. Original/candidate child processes must either both return with the required matrix/state relationship or both terminate with SIGFPE after the same recorded input and entry state. Matching trapped termination supplies no post-call value/state proof. Unsupported modes/traps are explicitly retained, not silently counted as exercised. The fixture does not restore raised flags around the tested component. A signaling-NaN predicate difference is a reported local difference, not silently waived and not by itself a full-adapter conclusion.

`analyze.py` requires exact frame ordering and full case coverage, unchanged caller input words, exact upper/diagonal words, unchanged entire nonfinite matrices, and byte preservation for all already numerically symmetric matrices including opposite zeros. It permits only replacing an unequal finite lower entry with its upper partner. State equality is checked separately from numeric policy. This does not establish the physical correctness of any newly admitted asymmetric input.

Two future compiled negative controls remove respectively the whole-matrix finite guard and the pair equality guard from the extracted insertion. Their output must demonstrate a matrix-policy failure: hidden nonfinite values and changed signed-zero words are discriminating cases. No passing negative-control evidence exists yet.

The proposed command is `run.py --execute --label LABEL --expected-plan-sha256 HASH`. Default `run.py` only checks source bindings and displays that command; it does not compile or run. `plan.json` fixes one CPU (12), one 180-second deadline for the entire compile/stub corpus, and a fresh ignored work directory under `.tirust-build/ew-invariant-symmetry-fixtures/`. There are no retries and no authorization-file mechanism. Execution requires separate task authorization naming the frozen proposal. The controller reuses the pinned reviewed process-group helper, retains raw logs and exit/reaping metadata on failures, and rechecks protected sources afterward. Binaries, objects and runtime logs stay outside the report tree.

The primary flags are the actual historical CT/TIRUST numerical flags `-w -fPIC -ffixed-line-length-132`; those particular objects had **no explicit optimization flag**. The component build substitutes only its private include directory for unrelated model/reducer include directories. The free-form driver uses the corresponding free-form line-length setting. A separately labeled O3 supplement adds `-O3`; it is not mislabeled as the historical object recipe. Both use the recorded gfortran wrapper and underlying compiler/linker anchors, the retained wrapper support files and system-runtime identities. Taskset is independently hash-bound. A small fixed environment excludes ambient Nix flag overrides; it is retained at invocation, without claiming historical-environment reproduction. Each future executable also has a retained explicit-loader `--list` result checked against the existing system-runtime anchors. No reducer archive or DSO is linked.

Successful execution would qualify only these extracted components, these cases and the recorded compiler/environment. Full adapter transport, QP decimal/cache-key parity, model input transport, real primary/reversed calls, physical coefficients, rescue rates, cache lifecycle and runtime acceptance remain outside this fixture.
