# Adaptive QP physical replay proposal

This is a frozen **source-only proposal**. No executable, loader, compiler,
library, performance worker, or numerical-lock operation was launched while
preparing it. Root review and separate admission are required before `run`.

The scientific question is whether the released adaptive bridge serves the 37
previously refused Gram reductions at the **same two physical inputs**, while
preserving every tensor and contracted result from the 363 previously served
calls exactly. The source of the executable is the completed private genuine
QP mass implementation, not the production generator. Its fixed CTModeRun=4
diagnostic is explicitly unchecked.

The original record has 200 native calls at each point. Point 1 serves all 200;
point 2 serves 163 and refuses 37 rank-three N4/N5 reductions. Its console has
74 W03 omission warnings, so its amplitude sums are incomplete. The original
failure values and messages remain in the frozen mass package. A refusal's
zero group-result placeholder is never a numerical reference.

The only changed native bytes are the TIRust bridge. The controller copies the
original `guarded-qp` executable, all eight input/card/resource files, and the
15-object declared runtime closure into an isolated ignored attempt directory.
Fourteen libraries are copied; the executable's original interpreter stays at
its pinned system path. All original library bytes are retained except the
bridge, which is replaced by the exact released adaptive bytes
`c5de24e6c41a90caf9e34684392d0193588522f26e6bbac646bdf74e5f151cb7`.

The replacement has no SONAME, exports the complete original ABI, and has
identical dependency names and version requirements to the original bridge.
The private copy is named `libmadloop_tirust.so` solely to satisfy the
executable's existing DT_NEEDED name; no ELF is patched or relinked. The
prepared manifest records both literal ELF metadata and byte identities. An
actual loader listing and a live `/proc/PID/maps` snapshot must match the
complete private runtime closure and executable before the run can qualify.
The filename never stands in for the mapped byte identity.

The existing observer captures binary128 model/mass/kinematic/numerator inputs,
native scale, all invariant and shift bits, cache/check controls, group order,
backend/status/error records, four raw tensor slots, contracted group results,
host IEEE flags, final amplitudes, accuracies and public codes. Every old/new
input and cache/check value must agree. All four raw tensor arrays, contracted
results and stability values must remain bitwise identical for each previously
served call. The 37 refused calls receive individual before/after status,
error, result and input-digest records. Sticky flag timing differences are
retained as observations. The strict inherited parser and warmup/point-end
validator reject truncated journals and incomplete worker completion.

There is **no new precision observer, relink, or build**. Per-call working
precision and adaptive-tier counts are therefore unavailable in this physical
diagnostic. A newly served call is not labeled a 512-bit call. The separately
qualified release Fortran transport package proves its own 256-to-512 policy
and telemetry behavior only; those observations are not assigned to these
physical calls. The complete original evidence, including independent and
lower-precision controls, remains hash-bound and unchanged.

A result with no recorded native omissions requires all 400 observed calls to
be served, all observed groups stable, and zero W03 warnings over the entire
worker console. Even then, fixed CTMode4, a success status, and W03 absence do
not establish physical accuracy. Independent same-input reduction or explicit
precision-convergence evidence is the remaining truth gate; ordinary MadLoop
stability and rescue qualification remains separate. COLLIER's reported cache
bug is not changed or investigated by this proposal.

The controller reuses the reviewed owned-process supervisor and the common
numerical lock. A busy lock returns 75 without waiting or consuming an attempt.
After admission there is one attempt, one loader-list command and one physical
worker, one nonreserved CPU (12), 4 GiB address space, and a shared 180-second
deadline including setup, loader work, numerical work and scientific closure.
There are no retries. The supervisor's signal deferral additionally covers the
shared deadline signal so that cleanup retains process ownership. Failed
attempts, partial outputs and post-deadline administrative hash evidence are
retained. No installed library, source repository, card, configuration,
production source, or generator path is changed.

From the repository root:

```sh
source tools/tirust_env.sh
python3 -B docs/benchmarkfolder/experiments/adaptive-qp-physical-replay-proposal-1/test_analyze.py
python3 -B docs/benchmarkfolder/experiments/adaptive-qp-physical-replay-proposal-1/controller.py verify
# Only after root review, admission, and the existing native queue is terminal:
python3 -B docs/benchmarkfolder/experiments/adaptive-qp-physical-replay-proposal-1/controller.py run
```

Preparation was limited to pure file reads, ELF metadata decoding, source/spec
writes, and ten synthetic parser tests. `prepare` is a one-shot source-freeze
command; it has already been used for the accompanying manifest. No runtime
attempt exists as part of this proposal.

The first pure preparation draft incorrectly asserted a 16-object closure;
the frozen original closure actually has 15 objects. Its source and failure
are retained under `preparation-draft1/`. The corrected count changes no file,
runtime dependency, physical input, or scientific scope. No spec or runtime
attempt had been published by that failed preparation.
