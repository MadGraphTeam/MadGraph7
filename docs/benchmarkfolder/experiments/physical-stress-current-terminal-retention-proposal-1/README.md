## Portable reader contract

The future public API is `verify(root=None, *, read_bytes=None)`. It returns `{verified: true, index_sha256, preparation_index_sha256, summary}` only when both authenticated capsules and all applicable bindings verify. `verified` denotes evidence integrity, not successful physics. A terminal stage that retained numerical failures can still be a valid verified packet.

The callback accepts two namespaces: own physical relative paths, and `preparation/<physical-relative-path>` for the exact admitted preparation packet. Both `evidence-index.json` and `preparation/evidence-index.json` are included. `read_bytes.paths` enumerates exactly the union of the own index's physical files plus its index, and the preparation index's physical files plus its prefixed index. Compressed logical aliases are interpreted internally by each verifier and are not extra physical reader paths. No fallback, discovery, arbitrary parent traversal, or unindexed dependency is allowed.
