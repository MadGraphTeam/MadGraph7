# Source-only proposal: reuse the private512-bit bridge

This proposes one bounded diagnostic using the unchanged private topology-c executable, the original ordinary/stress/ordinary input stream, and an already-built private TIRust DSO. It does not authorize execution, change production, or qualify a physical result. No compiler or linker is needed. The complete256-bit six-run evidence remains frozen in the sibling `qcd-topology-rescue-native` package.

The selected library is `.tirust-build/ew-threshold-512/runtime/libmadloop_tirust.so`, SHA256 `e8b65f86b78f77d8090e7c406274da32920d89279ee4d5d3ef40e518fb05afdc`. Its retained build record binds the historical dependency artifacts and unchanged before/after inputs. Its source is exactly the historical49af bridge with three functional replacements: working precision256→512, and both full/poles MP guard expressions2^-136→2^-(512−120)=2^-392. One comment also changes. Input parsing and input-precision policy remain113 bits. The DP source path, lightlike threshold2^-100, fixed affine-relation tolerances, caches, scalar backend and conventions are unchanged.

This therefore changes **arithmetic precision and admission policy together**. The threshold has consumers beyond the reported Gram guard, including modified-Cayley and other reduction guards. This one comparison cannot identify how much of a change comes from arithmetic versus admission. It does not weaken the production256-bit guard. Higher arithmetic precision cannot restore information lost when the113-bit inputs were constructed.

The pure ELF reader confirms the same12 public bridge ABI symbols and SONAME. The private DSO adds no runtime symbol-version requirement; it omits the historical library's `GLIBC_2.32` requirement. The unchanged topology-c executable uses `DT_RUNPATH`, allowing a controlled `LD_LIBRARY_PATH` substitution. This is loader suitability, not numerical certification. The same private512 DSO previously failed EW tensor qualification; its availability does not make it a trusted oracle.

The proposed new controller must use a fresh process/context and result directory, CPU11, one thread, the shared numerical lock, a180-second hard process cap, and zero retries. The existing frozen runner deliberately requires49af and must remain unchanged. The new controller will preserve the exact executable, cards, inputs, repair, mass transport, coupling policy, observer and normal cache policy (`TIRustGlobalCache=-1`,268435456-byte budget). The earlier EW tensor replays disabled caching; this proposal explicitly retains the full-amplitude policy. Contexts cannot share cached numeric values between DSOs or processes.

Before launch, the controller must verify all proposal pins and every copied resource byte, resolve the runtime with only the declared DSO substitution, and record its positive environment allowlist. It must also capture the actual loaded DSO path/hash from `/proc/PID/maps` after launch, without a preload or numerical instrumentation hook. An interruption or timeout must kill and reap the owned process group. Missing runtime capture, any drift, failed trace health, or ordinary parity failure remains a failed attempt; it must not trigger an automatic retry.

The existing256-bit topology-c/backend9 and NinjaRS topology-c/backend8 runs are the retained comparators; they need no rerun. Capture every actual CT4/5 group visit, native status/error, defined tensor result, aggregate finite/single/double coefficient, host status, and IEEE flag. Failed tensor outputs remain undefined and must not be interpreted. Require exact ordinary rows/raw words/status/flags and zero observer faults. For the stress point, compare the original physical input, actual repaired C, Born, numerators, masses, shifts, scales, supplied matrices and clamp sequence against the retained inputs. If the host legitimately changes call coverage, report it explicitly rather than fabricating missing calls or dropping new ones.

Offline interpretation must separate the39 massless, six bottom and six top historical TIRust refusals. The bottom square-before-promotion discrepancy remains unchanged and cannot be attributed to working precision. Compare each defined256/512 tensor, independent direction results, full Laurent coefficients against the retained NinjaRS comparator, and the universal double pole from the actual Born/coupling. Host acceptance or cross-backend agreement alone is not full physical truth, and the finite/single NinjaRS values remain an independently unproven comparator. No production or performance claim is permitted from this experiment.

`prepare.py` only reads and hashes sources/ELF files and writes the source proposal. `verify.py` checks the portable inventory and rederives it without loading any library. A separately reviewed controller and explicit root approval are required before the proposed process can run.
