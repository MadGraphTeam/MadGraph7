Exact loop-model preparation¶

Partly historical: the model preparation (loops.model, loops.compiler prepare_loop_request_model) is shared with engine v2; the kernels, recurrence, physical programs and oracles described for the per-diagram legacy one-loop engine were removed on 2026-10-29 (MQ-LEGACY-REMOVE; see loop_v2/DESIGN.md §13.3).

pyamplicol.loops.model.build_loop_model(raw_sidecar) prepares exact scalar definitions and individual tree/UV/R2 colour × Lorentz × loop-group entries. It consumes the existing raw UFO sidecar, including its exact-source contract; it does not import a second source manifest. Scalar definitions are indexed by (collection, raw_object_id). Vertex display names need not be unique.

parse_exact_ufo uses standard Python AST/tokenization to validate arithmetic syntax and retain numeric lexemes. Fraction converts decimals into exact rationals before the existing UFO parser runs. The parser and Symbolica own complex arithmetic, model-function calls and expression transformations. No Python expression evaluation or binary64 conversion occurs on this path. Unknown model functions retain their raw definitions and remain symbolic; arbitrary Python helper bodies are not interpreted.

ScalarDefinition.value is a LaurentExpression. CT dependencies, including ordinary parameter or coupling aliases containing CT/Laurent definitions, are substituted before requesting a coefficient. The full expression remains available. series(maximum_power) returns Symbolica’s native series and its remainder order; coefficient(power) extracts a native exact coefficient. For example, an O(epsilon) term multiplying a pole is retained in the finite part. Ordinary epsilon-independent parameter definitions remain separate, so input values and formal colour constants are not prematurely substituted.

CovariantKernelCatalogue(ir, structural_model).lower(entry) produces separate native TensorExpression objects for colour and Lorentz structure. The structural input is a native HepKit model or its public normalized JSON mapping. Only species and propagator metadata are reused. Cached numerical scalar values from the normalized model are never used for the entry’s coefficient. Each component is localized by a public HepKit single-vertex diagram with unit scalar coupling and the other tensor domain set to one. Component results are cached. This reuses native UFO index, momentum, gamma and colour lowering directly.

The local momenta are all incoming native q_edge symbols. leg_half_edges identifies the UFO leg order. Each tensor retains its native axis order, which can differ: Metric(1,4)*Metric(2,3) has axes (0,3,1,2). Consumers must use the native slots/index labels and native axis permutation/rebinding operations. The coefficient stays separate from both tensors.

The initial loop_sm controls cover every pure-QCD component, all 57 active four-gluon R2 basis entries, and two-point UV mass insertions. A synthetic one-point UV rule checks native scalar lowering without extending process support. A mixed QCD/QED quark-photon R2 control checks the exact model formula. Run these controls with PYAMPLICOL_NLO_UFO_REFERENCE pointing to loop_sm and a licensed Symbolica runtime. No reference files are changed.

This preparation does not certify a scheme, UV/R2 completeness, arbitrary precision physics, or formal-Nc continuation. Loop-group alternatives and particle counterterm metadata are retained; process-dependent matching, external-wavefunction insertions, restrictions and scalar-kernel compilation remain separate work. The active four-gluon loop_sm R2 coefficients contain fixed SU(3) constants. Preserving them does not reconstruct their Nc dependence. Formal-Nc identities of colour parameters (CA, CF, TR, …) are never assumed: a model supplies them in its LoopColorDeclaration.parameter_identities. Legacy inconsistent non-QCD Lorentz spin signatures fail when requested.

Exact restrictions and external requests¶

prepare_loop_restrictions(raw, simplify=True) applies the captured restriction card to a derived raw declaration view and retains the original unchanged. The installed UFO ParamCard parser owns block/LHA addresses. Source-line annotations in comments preserve the original numeric lexemes; its binary64 values are never used. Every source record and address must survive exactly, so duplicate records (including values that round to the same double), malformed headers, scans, continuations, nonfinite literals, scale-dependent blocks and decay tables are rejected. As in MadGraph’s restriction reader, an entry whose LHA address names no external parameter of the model (for example DECAY 15 in models without a tau width) is ignored and recorded under ignored_entries; names and comments never bind an entry. Signed decimal and Fortran D-exponent literals are exact. Complex parameters require both real and IM blocks; an IM entry only addresses a complex parameter, and partial component updates are explicitly unsupported and cannot erase an omitted component. All restriction cards shipped with loop_sm, loop_qcd_qed_sm and loop_qcd_qed_sm_Gmu load, except Gmu’s restrict_parallel_test.dat, which assigns SMINPUTS 1 twice and which MadGraph 3.7.0 rejects as well.

Nonzero entries replace adjustable defaults. Simplification fixes exactly zero external parameters, including omitted exact-zero defaults, under the existing loader convention. It does not identify equal nonzero parameters. Structural lowering carries these fixed values into scalar binding and rejects contradictory overrides. Without simplification, even a zero-valued adjustable mass retains its structural massive classification. The existing raw restriction metadata holds this result; no additional identity or manifest is introduced.

prepare_loop_external_request(model, incoming, outgoing) resolves particle names or PDGs through the native model. It derives directed scalar/Dirac/vector state kinds, structural helicities, component offsets, initial spin and colour averages, and identical-final factorials. The complete divisor follows the existing physical engine: initial spin × initial colour × identical-final factor, with couplings retained in the local kernels. Ghosts, Goldstones, nonpropagating states, Majorana fermions and unsupported spins/representations are rejected. This is request preparation, not a process capability certificate.

source_bare_program and source_model_program now use these model-derived defaults when state kinds or normalization are omitted. Existing explicit internal overrides remain supported. The derived defaults are retained as plain request metadata for the existing artifact boundary. Complete neutral source controls exercise the defaults against independent Born/bare/UV/R2 references, per-point scales and retained model snapshots in all three carriers. Public loop generation remains guarded until portable plan integration and selected-model capability checks are complete.

prepare_loop_request_scope may exclude a source basis before native tensor lowering only when an explicitly bounded coupling power proves it cannot occur. Every source coupling first requires declared nonnegative integer order data. Ordinary rules use the conservative coordinatewise union of Born/loop upper bounds; CT rules use loop upper bounds. Missing or unbounded coordinates do not exclude anything, and lower bounds cannot prune local factors. Original basis keys, including CT loop-group indices, and each exceeded-bound witness remain available in the scope. The full raw source and scalar program remain intact.

Scoped structural lowering retains the same raw object, and a source physical call must use the bounds that prepared it. Species perturbative-order facts come from the full ordinary source catalogue after exact-zero pruning and before request pruning. The graph builder validates these facts against native species/order declarations and uses its existing joint-correction eligibility formula; removed vertices cannot erase eligibility metadata. Scoped local CT coverage requires exact equality with every admitted source CT key and no unavailable entries. This covers local bases only: particle field counterterms, graph-derived correction eligibility, tensor conformance, selected Born/loop pairings and the physical scheme remain separate required checks. Unscoped callers retain the complete-source catalogue guard. The real loop_sm pure-QCD graph control uses this proof to exclude an unrelated QED scalar basis with an inconsistent source spin signature; the unscoped model still rejects it.

loops.compiler.prepare_loop_request_model connects these boundaries without process-name dispatch. It consumes either an existing CompiledModel raw UFO sidecar or an explicit RawLoopModel; normalized binary64 parameter defaults are not used. The returned preparation retains its compiled owner, original and restricted declarations, scope, native structural model, one paired scalar program and the selected complete local CT catalogue. Its compile method resolves physical external identities and forwards exact request bounds to the existing native complete engine.

The source catalogue reuses the exact-key local neutral-lepton, fundamental FFV and gluon tensor certificates. Unknown bases stay present and reject if matched by the requested process. It does not replace source coefficients, infer an absent UV scheme, or certify formal-Nc continuation of fixed-SU(3) four-gluon R2 rules. The source-QCD four-quark control agrees separately in bare, UV, R2 and total Laurent coefficients with independent MadLoop components in double, double-double and AP60. Exact analytic Born/UV controls test source parameter updates beyond binary64 and per-point scale binding. The same facade also exercises the complete neutral Gmu source. Source particle-field factors use the same paired owner and scale binding, as described below. Public generation and portable source-plan admission are unchanged.

Local colour alternatives¶

loops.color_terms.split_local_color_terms expands one native local factor and retains each independent colour tensor. The existing single-colour separation proof classifies the local monomials. model_basis_terms instead consumes the unsummed UFO entries directly and extracts an explicitly selected epsilon coefficient. It does not select eligible loop groups; its caller must supply those entries after process matching.

ColorTermDAG wraps the coefficient DAG. An open ColorCurrent carries (coefficient_node, native_colour_tensor) alternatives. Only local basis choices branch, while previous Lorentz currents remain node references. At a named site, identical local tensors and dependency nodes reuse a coefficient instruction. Alternatives sharing that instruction add their colour factors using native tensor arithmetic, preserving multiplicity. Distinct coefficient instructions remain separate, with visible branch counts. There is no global Lorentz expansion, trace, colour approximation or inferred symmetry factor.

This primitive covers the physical four-gluon rule’s three independent local colour tensors and the model’s selected four-gluon R2 basis. Its tests include a two-site, nine-branch coefficient calculation against an independent native local contraction, exact scalar/node reuse, and R2 tensor-DAG construction. Graph insertion/rebinding, physical external states, process-level colour contraction and branch-growth optimization are separate integration steps. Local catalogue frames must be rebound before two distinct sites are combined; reusing their original half-edge labels would incorrectly identify indices.

Native counterterm process matching¶

loops.counterterms.prepare_counterterm_model appends homogeneous CT rules to the ordinary native model with a private insertion order. Exact Laurent scalar expressions remain unevaluated; aliases use the native coupling symbols, including their namespaces. The returned model must generate both the ordinary catalogue and CT candidates. prepared.process(..., counterterms=False) restricts generation to ordinary rules; use build_loop_process(..., ordinary_model=prepared.ordinary_model) so effective CT interactions cannot change perturbative species membership.

match_counterterms generates zero-loop trees with exactly one tagged CT. It compares their attached currents to actual admitted loops, matching the sum of orders on the cycle vertices rather than the total amplitude order. R2 and UVmass alternatives match the unique positive loop species; empty alternatives are wildcards. UVloop alternatives impose forbidden-species restrictions only. UVtree uses tagged tree generation without a loop witness. Alternative indices are retained: repeated identical alternatives deliberately repeat the insertion. The legacy UFO type UV is classified with MadLoop 3.7’s import rule: an identical two-particle pair is UVmass, otherwise UVloop. The reference is models/import_ufo.py:1571–1655 and madgraph/loop/loop_diagram_generation.py:1210–1525 in the supplied MG5 source.

HepKit finds components and excises each attached current. Excision’s artificial boundary can be incoming or outgoing depending on the original internal edge orientation, so its raw diagram ID is insufficient. Public Symbolica.Graph canonicalizes a metadata projection retaining native interaction IDs, interaction port slots, particle identities and directed flow, plus all physical external labels and states. Only the artificial boundary state is normalized. The native model fingerprint is checked before using these current keys. Tests distinguish identical external support with different internal rules and external label assignments. No canonical-labeling, traversal or graph-generation algorithm is implemented in pyAmpliCol.

The counterterm inherits its freshly generated tree weight, never the sign or symmetry denominator of a loop witness. Multiple crossed loops can witness the same insertion without multiplying its weight. Bivalent CT rules require a finite native generation bound: with one CT of valence at least two and ordinary vertices of valence at least three, max_vertices = n_external - 1 is exact. Ordinary one/two-point rules and CT tadpoles fail explicitly at this boundary.

Eight native controls cover Drell–Yan, crossed fermion boxes, repeated/wildcard alternatives, UVtree versus UVloop, joint correction selection and current identity. The full compatible loop_sm subset selects one R2_UUA and no UV insertion for photon-only QCD Drell–Yan. Source CT tensors are still uncalibrated: the bundled native model uses a different FFV spinor-slot convention from the standard loop UFO. Matching graphs does not validate that convention, supply external-leg wavefunction CTs, certify a renormalization scheme, or certify formal-Nc continuation. Missing species of a restricted ordinary model remain explicitly recorded as unavailable basis entries.

OrdinaryBasisRepresentative provides a narrow, explicit convention bridge. Its source ordinary basis key, native rule and colour/Lorentz slot identify the representative; its required calibration label records the caller’s prior physical control. Preparation checks identical ordered signed PDGs, spins and colour representations, exact ordinary scalar and coupling order, and exact colour structure. A CT can reuse that representative only when its source Lorentz and colour expressions equal the source ordinary basis exactly. The counterterm’s Laurent coefficient is retained. Native model symbols are used for substitutions, and approximate numeric atoms in representatives are rejected.

This does not infer any Lorentz convention from names or transpose a gamma matrix. The first explicit mapping is the source u~ u A vector current to the bundled native V_132 basis (0,0). Each CT rule records its proven source identity and whether all entries have a representative. Unmatched structures remain uncalibrated; chiral, Sigma and new two/four-point structures acquire no certificate from this mapping. A calibration label alone is not a physical validation result, and the whole-model convention flag remains false.

Native fundamental colour traces¶

The current HepKit UFO dispatcher does not lower Tr: passing it through would leave a rank-zero scalar with unresolved colour indices. model_color prepares that head through public tensor.trace, TensorExpression.color_t, and typed HepKit UFO indices before native graph localization. The original sidecar colour expression stays unchanged. Both local catalogue lowering and augmented CT model construction use this boundary. Unknown UFO colour function heads fail explicitly.

The initial trace envelope is SU(3) with distinct positive adjoint external-leg indices; negative dummy indices and other representations are unsupported. Native algebra and component tests establish actual adjoint ports, Tr(Ta Tb) = delta_ab/2, cyclic invariance, and the noncommuting three-generator identity Tr(Ta Tb Tc) - Tr(Tb Ta Tc) = i f_abc/2. No private trace or colour algebra is implemented, and this does not establish general-Nc model validity.

tools/loop_reference/ct_tensor_oracle.py independently compares the three loop_sm gluon two-point R2 Lorentz structures with generated ALOHA routines: p^2 g, p_mu p_nu, and g. It checks every polarization basis pair and a complex polarization pair at real and complex off-shell momenta, removing the explicit ALOHA -i*COUP convention. Native arithmetic is exact; ALOHA is binary64. The report records source hashes and 102 comparisons. This local check does not validate CT scalar values, a whole process, chiral tensors or arbitrary-precision physics. It supplies a separate primitive control rather than extrapolating the ordinary FFV convention bridge to new structures.

An independently controlled new primitive may be supplied explicitly through CountertermPrimitiveValidation and prepare_counterterm_model’s primitive_validations argument. The immutable record binds the exact source basis key, colour/Lorentz expressions, ordered PDGs/spins/colour representations and named conformance control. Preparation rejects stale expressions, wrong ports, missing entries, duplicate evidence and empty provenance. It retains the original tensor and exact scalar; it cannot authorize another basis entry by name alone. CountertermRule.has_validated_tensor_basis requires every entry to have either an ordinary correspondence or this independent primitive evidence. The record does not run a comparison, validate scalar renormalization or set whole-model validation flags. Supplying it is an explicit assertion that the named local control has already been performed for precisely these structures and ports.

External-field factors¶

loops.wavefunction reads particle.counterterm independently of effective vertex insertion. One key contains a power for each coupling order in the UFO’s original registry order, followed by the declared loop-group index. Exactly one unit power selects a one-loop field correction with two additional fundamental coupling powers. Higher-loop entries are skipped. Laurent arithmetic and CT-dependent alias substitution reuse the existing native scalar lowering. Particle-field values currently require exact expression strings or integers; unobserved float/complex attributes fail rather than acquire false exactness.

match_external_field_counterterms retains each already-generated Born graph and records its external-leg index, selected model factor and loop-alternative index. It uses the positive-PDG particle definition for the antiparticle too. Each allowed alternative contributes separately, including repeated alternatives; an empty alternative is a wildcard. The caller supplies the complete resolved forbidden-species set and, when needed, an explicit allowed amplitude-order envelope. This stream does not infer those filters from bare-loop order differences or require a loop witness. It creates no new graph or Lorentz tensor.

MadLoop’s import_ufo.py:1355–1383 and loop_diagram_generation.py:1290–1332 define this convention. In loop_sm, tWcft_UV already includes the field factor delta-Z/2: the two external top legs contribute twice that model coefficient to the Born amplitude. No extra half, loop integration factor or loop symmetry factor is applied. Physical contraction then uses the usual 2 Re(Born* CT). The separate field IR leaves scheme validation false; vertex CT matching’s external-field-completion flag is not silently changed by constructing it.

The executable tools/loop_reference/wavefunction_oracle.py derives these two top factors from the source model and evaluates all three Laurent coefficients in a native batch against isolated MadLoop external-field output. It uses the reference Born values and binary64 comparison, so it validates field scalar normalization and multiplicity, not a full amplitude or arbitrary-precision physics. Full native physical assembly is a separate integration check.

Physical fixed-Nf colour controls¶

The internal DY, distinct-flavour four-quark and massive top-pair factories accept color_accuracy="full", "lc" or "nlc". Their default full-colour path uses PhysicalColorSpace to contract the original native SU(3) tensors; formal_color=True selects the separate formal full-colour calculation. The direct-R2 gluon factory also supports these projections with six Born colour terms and rectangular Born/CT matrices. One admitted squared-order sector is still required. These controls do not certify arbitrary models or the four-gluon effective model R2 rules’ general-Nc continuation.

The physical path uses the dependency’s adjoint, dummy-index scoping, trace, Fierz, projector and dimension-invariant operations. It never materializes the external colour component grid. Born/loop and Born/CT matrices retain exact complex entries; averaging is applied once after contraction. Physical representation dimensions and literal scalar coefficients stay unchanged, so fixed-SU(3) effective rules need no general-Nc continuation certificate. Dense component contraction is retained only in small independent test oracles. One cold process owns a cache of exact native tensor-expression pairs; model values and event buffers never enter it. Open-tensor canonicalization is not required for cache correctness. An unresolved closed network uses the same dependency trace/chain expansion and canonicalization sequence as the formal helper, and unknown residual tensors are rejected.

physical_color contracts semantic native colour tensors with SUNColorSpace. Source Ncol, CA, CF and TF are bound explicitly to their exact SU(Nc) expressions. Numeric constants are never guessed to be Casimirs. Each CT alias coefficient is first split into exact Nc grades. The shared native CT executor evaluates the colour-free aliases for each grade, while projection acts on Nc^grade times the complete Born-term by CT-term overlap matrix. A single projected weight is never absorbed into an alias shared by multiple terms. Each field grade uses its corresponding columns of the full Born Gram matrix. All bare, local UV, R2 and external-field rows share one structural maximum degree across the finite and both pole outputs, before numerical model values or helicities are evaluated. Born squared has its own maximum degree. Projection retains degree P for LC and every degree at least P-2 for NLC, with Nf fixed. Nc=3 and the physical initial-state average are applied only after projection. Result metadata records both degrees.

The four-quark Born degree is 2 and its virtual degree is 3: the leading Born colour factor is proportional to Nc^2-1, while the virtual CF factor adds one power. Fixed-Nf quark-loop and heavy-quark decoupling terms can have degree 2, so NLC retains this odd suppression as well as degree 1. For DY the respective degrees are 1 and 2. Actual particle identities, loop-particle alternatives, coupling orders, scalar expressions and Laurent coefficients remain source-owned. No mass, Yukawa or CKM parameter is equated by this local admission.

charged_ffv_oracle.py generates unchanged ALOHA FFS4_1 and FFS4_2 currents with unequal masses, independent complex Yukawas and off-shell complex momenta, then contracts them with FFV2_0. Both charge orientations of the source bbar–t–W- and tbar–b–W+ rule match the reference. Raw UFO endpoint slots are checked before the existing typed endpoint translation; exchanging the current bindings follows that declared frame change. No new gamma or colour algebra is introduced. Negative local tests retain rejection of changed colour tensors, reversed ports and uncalibrated Lorentz structures.

The independent complete-process control is u ubar -> d dbar with unrestricted Wolfenstein CKM, mixed QCD/EW Born sectors and QCD corrections only. The full SM source retains photon, Z and W Born exchange and the charged R2 insertions. All three Born squared orders and all three virtual squared orders, including both contributing Born–loop pairs at QCD4/QED2, agree with native MadLoop Laurent outputs at three exact massless points. The fixture records averaging, physical couplings, scales, restrictions and all changed model parameters. This is not a validation of jointly selected QCD+QED corrections.

The same saved precision-independent plan is checked through the shared native executor in double, DoubleFloat and arbitrary precision, including resolved helicity reconstruction, original lane identifiers and parameter increments below binary64 resolution. The provider comparison remains a binary64 check; precision-preserving transport and internal inclusive/resolved agreement do not turn its reference values into an arbitrary-precision oracle.

Exact semantic colour views of source scalars¶

prepare_source_color_scalars prepares a cold symbolic view of an existing source scalar program. Callers supply explicit ordinary-parameter identities, for example CA -> Nc and CF -> (Nc**2-1)/(2*Nc). The preparation checks their exact agreement with the original source at Nc=3; agreement only at the default external parameter values is insufficient. No numeric constant is interpreted as a colour invariant. Additional symbols must belong to the source binding layout or to the original exact expression.

The identity is substituted before dependent source declarations are expanded. Its original active diagnostic remains paired with its value, including mutable external-input conditions and inactive branches. Replacing an adjustable external parameter is rejected unless it was explicitly fixed at generation; ordinary native updates then reject changes to that fixed parameter. This avoids silently accepting parameter updates that the colour view would ignore.

SourceColorScalarPlan retains the formal paired plan and an ordinary ScalarBindingPlan containing Nc-independent coefficient outputs. grades and columns map each colour grade back to the original scalar output. The existing output epsilon powers are unchanged. Symbolica and the existing colour projection helpers perform Laurent collection, including Nc-independent runtime conditionals. Nc-dependent diagnostics, unsupported predicates and non-Laurent functional dependence fail explicitly. Every coefficient retains its source diagnostic, including exactly zero coefficients; an all-zero catalogue has a zero grade solely to preserve diagnostic evaluation, not to set a physical leading colour degree.

The coefficient plan shares its ScalarProgram, external layout, exact defaults and fixed-parameter map with the ordinary source owner. NativeScaleBindings evaluates it using the same atomic global snapshot and native per-point scale rows. Saved prepared views retain this behavior in double, DoubleFloat and arbitrary precision, without retaining a source producer or a second numerical parameter engine.

This boundary does not certify a model’s general-Nc continuation or enable public LC/NLC generation. Physical integration still requires exact scalar-alias incidence on local tensor terms, a common structural degree per squared-order sector across bare/UV/R2 and all pole coefficients, and a formal continuation of every selected effective rule. In particular, the fixed-Nc four-gluon R2 source cannot be generalized by substituting its named CA/CF parameters alone.

scalar_alias_incidence supplies the next preparation boundary for counterterm colour grading. It asks Symbolica to collect each existing local coefficient kernel in its counterterm aliases and input placeholders, then propagates only alias support and homogeneous degree through the DAG. Final scalar outputs must have degree one in the selected insertion aliases; zero outputs are accepted. Nonpolynomial alias/input dependence and alias-independent or nonlinear contamination fail with the offending kernel/output identity.

Incidence support alone must not set the leading colour degree: different nonzero alias coefficients may cancel within a tensor term. A separate exact grade pass substitutes their values into each local kernel before collecting it, propagates proven-zero components, and uses canonical references for equal local expressions with equal dependencies. Thus (g1+g2)*J vanishes for a grade with coefficients (1,-1) and cannot set a spurious leading degree. No nonzero whole-current expression is expanded into a downstream kernel. Distinct remaining currents define structural support independently of numerical helicity or parameter cancellations.

NativeModelVirtualProgram uses these grade-aware masks in place of its blanket rejection of mixed-grade, multi-term insertions. The source-model continuation gate remains in place; incidence and local zero propagation are not by themselves a general-Nc model certificate.

Projection by squared coupling sector¶

The cold physical projection now uses the existing exact order-pair catalogue. A rectangular Born–loop matrix cell belongs to the sector of its left Born order and right loop order; a Born matrix cell similarly belongs to its Born squared order. Counterterm and external-field rows supply the left order and their actual insertion graph order explicitly. Missing pairings are zeroed and cannot set a sector’s leading degree. Each virtual sector combines its bare, UV, R2, field and epsilon rows before selecting a common structural degree. Born sector degrees are independent, and structurally zero sectors retain None on their original catalogue axis.

The right insertion order is established before projection: source preparation groups every actual CT entry by vertex, loop-particle-group and exact coupling order, and _rule_orders checks every native coupling in each resulting rule. Graph snapshots sum these homogeneous vertex orders; matching removes only the auxiliary CT insertion tag. A focused source control checks one vertex with multiple coupling orders and loop groups, preventing a representative coupling from silently determining the whole rule’s order.

Projection reassembles the same rectangular matrices and recompiles the existing weight evaluators. It does not duplicate coherent currents or create another numerical engine. PhysicalColorProjection.born_degrees and virtual_degrees retain the catalogue-aligned degree vectors; the older singular degree fields are set only for a single corresponding sector.

Retained model-rule views now preserve these exact projected weights, their catalogue-aligned degree vectors and their declared accuracy while rebinding arithmetic. The PACBIN plan has an optional color_projection descriptor with the same accuracy and degree vectors; its numerical evaluator states already contain the fixed-Nf projection evaluated at Nc=3. Core loading checks the accuracy and order-axis lengths. An absent descriptor describes existing unprojected full-colour plans. Portable binding restores the saved accuracy, instead of labelling every loaded plan as full colour. Projected dimensional numerator/direct-R2 transport remains explicitly unsupported in this slice.

Complete model-rule Drell–Yan controls cover full/LC/NLC PACBIN reload and rebinding in double, DoubleFloat and arbitrary precision, including exact parameter changes and native helicity-row reconstruction of every inclusive component and Laurent coefficient. Mixed-order bare controls separately retain all Born and virtual degree axes through rebinding. Publication checks compare declared accuracy with the saved descriptor: the current full-only public boundary cannot hide an LC/NLC projection. Source-model continuation and public resolved LC’s signed Born-component contract remain integration requirements before public source LC/NLC can be enabled.

Explicit four-gluon QCD rational continuation¶

qcd_r2_color.prepare_qcd_four_gluon_r2 supplies a whole-rule HV continuation from 2007.03713, Eqs. 5.30–5.38, using Tr(Ta Tb)=delta_ab/2. Its scalar coefficients carry formal Nc, while native fundamental/adjoint tensors retain the physical source port frame for the existing SUNColorSpace lift. The library performs tensor construction and contraction; pyAmpliCol declares the published local rule.

Preparation requires an explicit source group, gauge-coupling expression, contribution (gauge or fundamental-dirac) and HV convention. It compares the complete original source tensor at Nc=3, including scalar coefficients. Both source and replacement lie in the checked three-metric-product span; every SU(3) colour component of three independent Lorentz components is compared exactly. The active 57-entry UFO gives 24,576 component agreements. A separate formal-Nc test uses 0903.0356, Fig. 2, a different published decomposition, rather than reusing the implementation.

The immutable record is keyed by original collection, vertex, loop group and order. It retains the original entry objects, including source diagnostics and all loop alternatives. One Dirac fundamental species per alternative and the complete Yang–Mills gauge/ghost contribution are this local rule’s certified domain; the single-species requirement is not a general loop-group capacity limit. No Nf aggregate or per-entry substitution is inferred, and source/model names play no role in conformance. A partial group, incompatible species, changed scalar normalization or unsupported scheme fails explicitly.

This local preparation alone does not alter process counterterm generation. The explicit source binding described below applies the replacement once per eligible original group, retains source diagnostics and species multiplicities, and enforces HV parameter ties before the common sector colour projection. Local Nc=3 agreement alone is not broader model, UV or scheme certification.

Source-owned continuation and coefficient grades¶

SourceColorContinuation is explicit prepared-model data: the actual source model, formal Nc, exact parameter identities, declared source kernel and particle-field keys, and the existing complete scheme declaration. It does not infer colour semantics from a model name or numerical constants. Missing continuation for a selected kernel/field names that exact key and fails the projection request. Whole rules whose numerical SU(3) coefficients do not define their continuation still need independently checked replacements.

The generic source_model_program accepts this internal continuation. Before projecting, it checks every selected ordinary scalar output, including derived masses and couplings, for exact Nc independence across the full external parameter space. Nontrivial ordinary scalar colour dependence is currently an explicit unsupported feature; it cannot pass by matching default numbers. Original conditional diagnostics remain attached to the exact source formulas.

Model UV/R2 and external-field coefficients then use one shared source owner with a graded NativeScaleBindings view. Each current’s alias columns select its exact degree and epsilon coefficient. The existing local incidence and zero-propagation proof controls its colour weights; zero field coefficients cannot raise a sector’s leading degree. The original diagnostic accompanies every grade. Saved plans retain these ordinary exact scalar/evaluator states and source column maps, so numerical evaluation uses the same batched shared core and precision rebinding path as full colour.

Source Drell–Yan controls check the complete model-rule result in all three carriers and through saved plans. The independent fundamental colour factor predicts LC/full = 9/8 for every virtual component and NLC = full. The tests also vary exact inputs and per-point scales and reject a missing selected rule. These controls supply explicit model data and exclude the fixed-SU3 four-gluon R2 rule; they are not a universal loop_sm continuation certificate or public LC/NLC activation. Public resolved LC must still supply its signed Born-component observable contract.

An unrestricted-CKM source u u~ > d d~ control additionally preserves all three Born and virtual squared orders and matches the independent MadLoop finite and pole values after formal-full projection. Its correction selection remains QCD, not joint QCD+QED. A source u u~ > g g control covers nonzero external-gluon field renormalization: the heavy-flavour contribution is absent at LC and retained at NLC, and its graded source columns survive PACBIN loading. Vanishing Laurent components are compared at Born scale to account for cancellation roundoff, without discarding any returned coefficient.

Binding whole-rule colour input to a source process¶

The source coefficient consumer keeps the original CT coupling outputs in its paired scalar plan when a checked whole rule is substituted. Every original active diagnostic is evaluated even if none of the new coefficients uses the old value. Replacement aliases select separate exact local coefficients. Their referenced ordinary source parameters are resolved by the existing scalar frontend and remain diagnostic-bearing outputs of the same source owner; neither source defaults nor intermediate values pass through binary64.

The complete formal plan is graded once. Counterterm recurrence incidence uses the active replacement aliases, while matching, loop alternatives, coupling orders and signs continue to use the original rule. This retains per-species eligibility and avoids assigning guessed Nc factors to the original numerical four-gluon coefficient table. Saved plans carry the resulting ordinary coefficient evaluator bytes and column maps, with no separate numerical path.

SourceColorContinuation now checks the identity of every actually applied whole-rule input against the declaration. Scheme parameter ties use the existing shared fixed_parameters mechanism: a required value must hold symbolically over the entire runtime input domain. An external scheme parameter must therefore be fixed during preparation, and an attempted update is rejected atomically. An internal expression must reduce to the required value with the same fixed map. Scheme declarations alone cannot establish these ties.

The explicit test-support profile tools/loop_reference/qcd_source_color.prepare_loop_sm_four_gluon_color supplies the source names G and lhv, always requires HV with lhv=1, and runs whole tensor/scalar/species conformance on each selected four-adjoint-vector R2 group. It preserves all unrelated caller declarations and original CT evidence. Model display names do not grant admission, and this helper gives no certificate to unrelated rules. It returns the prepared model with the checked native rules and the matching source colour declaration; those objects must be used together.

These remain internal prepared-model interfaces. Public LC still requires its signed Born-component observable contract, and a generic model needs declared, validated continuation for every selected ordinary, UV, rational and field structure before projection is available.

Retained directed projectors on a source owner¶

PreparedDirectedBare and PreparedDirectedModel retain immutable dependency instruction bytes for the directed Born contraction, each denominator family, local UV/R2 and external-field terms, and final complex assembly. They refer to existing retained bare/model plans. Binding a different arithmetic carrier uses those bytes and the original source scalar/current owner; it does not regenerate colour algebra, diagrams or counterterm currents. A different plan is rejected. NativeDirectedModelProgram accepts a NativeSourceModelProgram through its existing .virtual owner.

The two Born–loop terms remain separate through complex reduction. Only then is the swapped second term conjugated. Local rules retain their individual order pairings; external fields retain the corresponding Born-graph mask and delta-Z/2 factor. Ordinary real-result projection is not applied to directed histories. The complete Python control wrapper uses dense internal helicity/reduction rows and reports original physical point IDs separately from the direction/order/ family catalogue, including IDs at the native integer boundary. This is not a partial-batch scheduler or precision-rescue implementation. Early state/current exceptions and some finite-value guards still expose the legacy dense row context; typed original-ID failures at every stage belong to the subsequent native correlated scheduler.

The actual source u u~ > d d~ [QCD] control covers identity, a colour Casimir, complex swapped histories, all UV/R2 components, two exact on-shell points and scales, all three arithmetic carriers, and below-binary64 parameter changes. Independent analytic Born/UV expressions supplement transport checks against the ordinary source projection; sharing currents is not independent physics validation. Source-directed artifact serialization, native/public correlation scheduling, spin-source transport/compaction, correlated LC/NLC and flavour mappings remain subsequent work. Existing internal spin controls remain separate.
