Exact loop flavour and external-port transport¶

Historical: this describes the per-diagram legacy one-loop engine, removed on 2026-10-29 (MQ-LEGACY-REMOVE; v2 is the only one-loop engine, see loop_v2/DESIGN.md and §13.3 there). The modules, tools and tests named here may no longer exist.

loops.flavor_transport.IdentityFlavorTransport.admit connects an existing FlavorSymmetry to two actual NativeSourceModelProgram instances. The representative and independently generated member must share the exact retained source model and scalar program. The complete ordinary generation allow-list, UV/R2 owner, request scope, correction selection, ordered external states, normalization, order pairings and graph conventions are checked. External PDGs come from the actual native Born graph as well as the source request; supplied process metadata alone cannot admit a relation.

The species proof remains species-only, with external_transport_validated=False. The separate transport record retains both prepared identities, actual requests and the existing LegMapping. Its first supported relation is orientation-preserving species substitution with unchanged external port order and unit factor. This imposes no bound on the number of legs, orders, histories or related members. Nonidentity permutations and charge conjugation need separate transport proofs. Literal vector sources additionally require the paired source admission below. Ordinary full-colour resolved helicity axes are checked for equality during admission and preserved by identity-port transport.

relation.bind(representative, directed=prepared_directed) creates a member view of the representative’s existing batched numerical executors. It passes through whole result objects: Born, every squared order and Laurent coefficient, bare, UV, R2, local and external-field pieces, and both complex directed interference terms. It neither fits an overall factor nor relabels numerical coefficients. The directed operation order and physical/auxiliary labels are unchanged because the external ports are identical. Original point IDs remain the executor’s opaque IDs. Empty batches retain all existing result axes.

Updates act on the representative’s atomic source owner. Structurally shared parameters stay shared; parameters fixed during generation cannot be changed through the member view. Rebinding precision uses retained instructions and the original exact source inputs. The independently generated member is an admission and validation input, not a second mutable numerical state consulted during mapped evaluation.

Formal-colour species prerequisite¶

RetainedFlavorPlan.source_color optionally retains the actual SourceColorContinuation. Its cold proof requires every ordinary, UV/R2 and field rule in the retained request scope, including declared scheme ties and all Laurent powers. It compares exact formal values and active diagnostics; equality after substituting Nc=3 cannot establish the symmetry.

Whole-rule R2 replacements retain their original complete UFO group and their separate native coefficient/tensor slots. The proof checks every alias, ordered port, coefficient, coupling power, tensor and source multiplicity against the owned replacement. It does not assume entrywise correspondence: the loop_sm four-gluon replacements have 28/29 original entries and 12/24 native terms.

The source-colour formal_scalars API exposes the same checked paired source expressions before numerical grading. This lets the cold proof compare heavy counterterm diagnostics whose opaque source-helper arguments contain Nc. The existing scalars execution API still rejects unsupported Nc-dependent diagnostics and performs its unchanged colour grading. A cold symmetry proof is not a numerical grading certificate.

The complete declared loop_sm QCD request model passes exact d/s symmetry over 9 ordinary rules, 64 UV/R2 rules and 6 external-field rules. Independent tests reject altered replacement tensors/aliases/orders, unequal symbolic colour continuations with equal Nc=3 values, hidden positive-epsilon coefficients and different active diagnostics. Projected process transport remains a separate gate: actual common degrees, signed LC component axes and source catalogs must be proved for the independently generated members before public reuse.

The producer admission now checks that formal LC/NLC/full owners retain the exact continuation in both their model constructor and immutable prepared record. It validates the actual formal metric owner, order domains, normalization and common degrees. Full colour does not bypass this check when it was constructed through a formal continuation.

For LC, admission reconstructs the canonical Born-tensor partition using the dependency and verifies its complete typed open ports. Each signed component must have the same exact tensors and absolute coupling orders, including multiplicities, in the same public axis position. The independent d/s controls have different raw Born-column memberships but identical semantic component axes. Matching IDs or numerical Nc=3 weights alone cannot certify this relation. The existing partition must be prepared before capturing the model and directed source plans; it cannot be attached afterward to a different prepared owner.

Actual LC/NLC/formal-full owner controls cover absent/foreign continuation, paired mutable metadata substitution, changed components, typed ports, formal records and degrees. Projected nonempty histories additionally require both actual complete-family banks. Each bank must belong to its own model/formal owner; the pair must agree on formal Nc, accuracy, order sectors, complete typed history families, their common degrees and every requested family assignment. Each source class must retain the exact ordinary bank object. This comparison does not identify raw current columns or replace the species/scalar proof.

Binding and saving require the actually paired directed plan for projected nonidentity histories, including direct construction and rebind. An ordinary-only relation cannot acquire this capability. Existing safe fixed-full or projected identity-only composition is preserved; whenever admission retained a directed plan, equal-valued replacement is rejected. Native loading uses the existing complete-family convention and its full typed validator.

Thirty actual owner/source/writer/compatibility checks and six mapped LC/NLC all-carrier physical cases pass against independent member currents. Normal mapped checkpoints are saved. The native ingress test passes the actual identity/complete plans and seven malformed-family controls; the unified Python/SDK build and normal source staging pass. Nine saved full/LC/NLC cases cover all three carriers, complete components and totals. Public LC/NLC selection, sources, complex totals and a genuine subset AP rescue pass, as does the NLC binary64 standalone SDK client with owned outputs.

Saved artifacts and public selection¶

For virtual generation, process.flavor_blind = true requests exact candidate grouping. It does not authorize tree-style numerical or flavour-blind reuse. Every process is independently generated first. The complete retained model proof and actual prepared-program admission decide which identity-port members can share a representative. This first implementation therefore saves stored runtime instructions but does not avoid member generation costs.

Proved members use the existing ProcessGroupMap and the exact-loop-flavor grouping basis. They are not manifest ProcessAlias records, whose same-PDG permutation meaning is unchanged. The existing immutable loop PACBIN records admitted member IDs, expressions, external PDGs and the proved species relation. Its producer checks the actual prepared owner. Native artifact selection matches mutable process-group records against that admission before binding any numeric state. Changed species, factors, permutations, conjugation or unadmitted IDs cannot obtain representative access by editing process-groups.json.

Public process ID, expression and external-particle metadata describe the selected member. Public spelling is retained: the existing exact-first, uniquely case-insensitive particle resolver uses the actual source/native external-state catalog, so g can resolve to the model’s G. Hidden ghost or Goldstone names cannot shadow a physical external state. The entire ordered PDG sequence and incoming count must still match the admitted request; ambiguous or incompatible aliases retain independent generation. representative_process_key identifies the stored process. Ordinary resolved and directed histories retain every order, pole and component; the member uses the same exact scalar owner and parameter-update guards.

Unproved candidates remain independent. LC/NLC and formally continued full-colour requests may reuse a representative after the exact projected owner and component checks above. Nonidentity colour histories also need the paired complete-family authority described above. The existing canonical LC partition is prepared before capturing any model or source plan. If dependency canonicalization is unavailable for an otherwise executable correlated request, optional flavour grouping leaves that request independent; malformed owner data remains an error. Ordinary resolved LC still requires its signed component partition. Spin requests reuse a representative only after both actual source catalogs pass the additional admission. The existing generation filters report whether grouping was requested, transport was checked and reuse actually applied, with a reason when the process remains independent. A request flag is never a claim of a proved mapping. Ordinary group inspection retains each member’s actual proof basis.

Literal vector sources and paired admission¶

Generation prepares the ordinary directed plan and every declared joint source class independently for both processes before considering reuse. Admission compares actual prepared owners, ordered colour-history catalogs and port representations. Selected source species must stay fixed under the flavour map. Actual model-owned SourceIR, crossing-phase evaluator bytes and compact spectator helicities must agree. The existing NativeSpinSourcePlan factory derives the expected phase and spectator catalog once per owner at admission: two equally altered dataclasses cannot certify an unrelated phase or helicity layout.

The relation retains both actual class catalogs, with no fixed class or leg count. bind accepts only an admitted representative class. The PACBIN writer checks the exact catalog it saves against that admission; a missing, foreign, duplicated or unadmitted class cannot borrow the relation. Native cold validation also requires every selected source vector species to remain fixed by the admitted map. Existing typed source and process-group validation still applies.

Per-call source rows pass through the same native executor. No second crossing phase, conjugation or projection is introduced. Exact sources and model parameters retain their separate ownership during rebind, point compaction and rescue.

The exercised source composition is QCD d d~ -> g g and s s~ -> g g, with classes (3,), (4,) and (3,4). Fixed-full-colour owners cover identity/ordered/swapped histories; formal LC/NLC/full owners also admit nonidentity histories when the actual paired complete-family gate passes. The full retained QCD proof rejects the tested u/c substitution; photon-order scope rejects the tested d/s and u/c substitutions. Such processes remain independently generated. A matching default tree value is never a replacement for the proof.

Validation and current boundary¶

The independent source controls are QCD u u~ -> d d~ and u u~ -> s s~ from one prepared loop_sm request. Its complete retained source scope contains nine ordinary rules, 64 UV/R2 rules and six external-field rules. Each process is independently generated with one Born graph, 14 loop graphs and six families. Their entire component/order/pole outputs and four directed histories agree in binary64, DoubleFloat and ArbPrec70. The histories include a swapped ordered pair with nonzero imaginary interference, and compare first/second terms separately. Exact coupling perturbations beyond binary64 survive; a mixed update attempting to change a generation-fixed parameter fails before publishing any state.

The existing species-proof tests additionally reject independent equal-default masses and Yukawas, different charges, UV logarithms, loop-group multiplicities, positive-epsilon CT coefficients, unequal external-field terms and overridden native tensors. Numerical equality of tree samples is never a certificate.

Fresh public generation additionally compares the saved admitted member with an independently serialized member PACBIN in all three carriers. The ordinary case retains all 16 resolved helicities; the directed case checks separate first and second terms for ordered complex histories. Both cover every component, order and Laurent coefficient, per-point scales and opaque point IDs. Native selected member metadata, atomic fixed-parameter rejection and modified group-record rejection are checked on the saved artifact. These are correctness controls, not runtime performance measurements.

The paired spin-source extension independently generates the 45-loop d d~ -> g g and s s~ -> g g owners. Its ordinary and three source classes pass the same component/order/pole comparisons in double, DoubleFloat and ArbPrec70, including Casimir and swapped complex ordered histories. Fresh saved/public selection preserves exact parameter and source perturbations, arbitrary point IDs, empty batches and stored vector defaults through clear. An underflowing binary64 scale in one row is rescued with ArbPrec60/80 while the other rows retain their results. A cold artifact changing the selected vector species is rejected. A linked safe Rust SDK client checks mapped selection, reversed unequal joint source labels, invalid source rejection and result ownership after handles and input buffers are dropped. These controls share the fresh artifact; no second physics generation or native build is required.

The projected extension independently generates the declared formal d d~ -> g g and s s~ -> g g processes, then constructs checked LC/NLC/full views over each member’s actual graphs. Their three LC signed axes agree by canonical tensor and absolute order even though the raw Born-column memberships differ. Complete formal-full coefficients agree with the earlier independently saved fixed-full owners after matching the source inputs, including the bottom-mass convention; no tolerance or normalization adjustment is used.

The earlier public projected controls exercise ordinary and signed resolved LC/NLC in double, DoubleFloat and ArbPrec70, including all components, orders and poles, empty/singleton/irregular batches and opaque IDs. Independently saved identity source catalogues cover ordinary, both single-vector classes and their joint class, with separate first and second interference terms. Public LC/NLC/full selection checks member metadata, resolved reconstruction, exact sources and clear; a single failed binary64 lane is rescued with ArbPrec60/80. Cold changes to projected histories are rejected. A linked safe Rust SDK client compares mapped and independently saved LC/NLC ordinary/resolved/source values, verifies complete buffer lengths and shapes, and retains owned results after clear. These are correctness controls, not generation or runtime measurements.

The identity-port transport is model-R2 with UV and external fields, exact species substitution and unchanged external ports. Projected nonidentity histories now pass the source, native, saved/public and SDK gates above. Charge conjugation remains uncertified. The separate ordinary Bose extension below admits only its explicitly proved external-port action. Saved member selection uses the shared native artifact loader; it introduces no new manifest or hash. The original fixed-full-colour control does not use formal whole-rule or paired diagnostic lowering. Those paths are covered by the separately owned formal prerequisite above; unsupported dimensional continuations and unproved scheme changes remain outside its certified domain.

Explicit ordinary Bose members¶

An explicitly supplied LegMapping can permute identical self-conjugate bosons on the same incoming or outgoing side, within full-colour ordinary interference. This is an additional retained-source admission and saved-member transport. The public generator’s automatic flavour-grouping search still proposes unchanged external ports; it does not add a permutation search or infer a relation from numerical equality.

Admission preserves the complete species proof and checks the actual external states, normalization, correction orders and model-owned fields. Every eligible ordinary and UV/R2 local rule is compared independently under the existing adjacent-transposition Bose proof. Native coupling aliases expand through their exact source-owned scalar expressions, with every Laurent coefficient and paired diagnostic retained. When momentum conservation is necessary, both vertex tensors are routed with the same original dependency momentum basis; external wavefunctions and propagator factors never enter this local proof.

For a fixed-colour source rule, an opt-in dependency tensor-component comparison can establish an equality that symbolic expression expansion cannot reduce. Both tensors retain the same complete typed external interface, and every component remains an exact Symbolica expression. This does not substitute parameter values, epsilon or a named formal colour invariant. An actual formal colour continuation never selects this fixed-representation fallback. The external-field insertion multiset is recomputed from its source owner before checking permutation covariance; dropping an entire symmetric orbit cannot pass by symmetry alone.

The selected member uses the established relation q[r] = p[permutation[r]]. One native batch binding permutes exact momentum strings before either ordinary or verified evaluation. Scales, opaque original point IDs and global parameter snapshots keep their identities; a rescue subset reuses this already bound input. An independent non-involutive three-cycle control distinguishes this direction from its inverse and detects omitted or repeated application. Identical-boson physical amplitudes alone cannot do that.

Capabilities belong to the selected member. A nonidentity member carrying only the ordinary proof exposes ordinary inclusive evaluation; resolved outputs, colour histories and vector sources require their own axis/source proof. The proved named-history/source extension below is explicit. The saved representative keeps its real resolved and correlated plans. Inspection exposes both selected-process capabilities and representative_physics, so a richer representative does not imply an unproved member capability. SDK discovery and evaluation use the same selected capability decision.

The existing typed runtime record carries the admitted permutation, and the artifact loader checks it against the existing process-group relation. Old typed readers deny unknown runtime-record fields, so they reject this new nonidentity descriptor instead of silently evaluating it as an identity map. There is no additional manifest, provenance mechanism or public loop-amplitude API.

The exercised complete source pair is the independently generated fixed-full QCD d d~ -> g g / s s~ -> g g, with the two outgoing gluon ports exchanged. Every selected ordinary and local counterterm group passes the exact rule proof, and both actual 18-insertion external-field multisets pass their source-owner checks. Born, bare, UV, R2, local-UV, external-field and total coefficients agree in double, DoubleFloat and ArbPrec70, including exact parameter changes, empty batches and reordered points. Separate fixed-component controls reject physical asymmetry, a changed typed interface and an epsilon-squared coefficient whose formal-colour difference vanishes at three colours. An actual formal owner checks that its local proof never selects the fixed-component fallback.

Current saved/public controls compare every component, order and pole against the independently saved member in all three carriers, including irregular batches, opaque IDs and invalid permutation records. Public selection preserves the real representative’s resolved/history/source discovery while rejecting these unproved member operations. One underflowing binary64 scale is rescued with ArbPrec60/80, retaining its original point identity. The safe Rust SDK checks ordinary coefficients, selected capability discovery, rejected resolved and correlated calls, and result ownership after clearing/dropping the handle. These are correctness controls, not updated performance measurements.

Explicit Bose history and vector-source subsets¶

An ordinary admitted Bose relation can retain an additional immutable proof over the actual paired directed preparations and SourceIR catalogues. It proves a selected subset of the existing named requests; each selected ID keeps its original operator definition. The source-owned proof first checks that the member’s (id, definition) matches the saved named catalogue, then locates the inverse-permuted representative definition. Aliases are permitted and keep separate selected IDs. No identity/Casimir allowlist or permutation search is introduced. The exercised closed subset is born and casimir; the richer representative also retains ordered and swapped.

The initial physical colour ports determine which operator labels transform. Retired physical parents still transform; auxiliary labels stay unchanged, including positive labels equal to colourless physical slots. Existing typed colour connections validate the resulting history. Vector class keys follow the inverse leg permutation. Each side retains its actual SourceIR, crossing-phase and compact spectator authority, checked once when constructing the immutable scope. Replacing both sides with matching foreign metadata cannot manufacture this proof, and ordinary-only relations cannot be promoted by binding alone.

The existing member record carries the selected history IDs and proved source class keys. The normal writer rechecks the actual representative directed plan and every required source object; extra validated representative classes may remain available. A selected singleton need only have its inverse counterpart on the representative: the exercised member leg4 works with representative leg3 alone. The typed reader validates saved references and physical roles. Public and SDK discovery describe the selected capability while preserving the complete representative plans. Resolved and projected transport are not inferred from this full-colour source proof.

Native ingress permutes exact momenta and literal source keys once, before ordinary execution or verification. The existing SourceIR applies its phase once; there is no additional conjugation, rescaling or binary64 promotion. All complete Born/virtual component buffers, orders, Laurent coefficients, both integrated terms, status channels and original IDs are gathered after execution.

The complete representative bank executes before selecting output histories. A failure in an unselected history therefore remains a point failure. It keeps its original representative context in the diagnostic and has no selected history index; failures shared by selected aliases produce the corresponding selected diagnostics. Structured external-leg fields and every verification attempt follow the same map. This conservative failure policy does not claim that omitted output rows were never evaluated.

The independently generated fixed-full QCD d/s→gg source owners pass all three carriers with ordinary, singleton and joint vector classes, all nine component buffers and separate directed terms. The saved/public controls pass through normal artifacts, exact parameter updates, empty/singleton/tail batches, opaque IDs, malformed scope rejection and ArbPrec60/80 subset rescue. A distinct non-involutive exact-input test establishes routing direction and subset replay; Bose symmetry alone cannot detect consistently omitting both momentum and source actions. Tests also retain the old ordinary-only member denials. The binary64 SDK client checks selected versus richer representative catalogues, reversed literal joint labels, singleton inverse routing, complete values and owned results after dropping handles. These are correctness controls; benchmark cells have not been retimed for this milestone.

Directed colour projection reuse¶

The retained formal-full d d~ -> g g bank includes the common degrees of its complete order-two family (28 histories / 784 pairs), with exact requested rectangles in both directions. reproject_directed_color_bank can now construct a new full/LC/NLC bank for a normally projected model with the same complete exact colour support. Each side must retain its own coherent captured process, scalar producer/preparation, source-colour declaration and formal owner. Cross-owner process/scalar pointers and initial averages need not be equal: these are not premises of the colour algebra. The resulting identity rows are checked against the target’s ordinary weights. The reference bank never changes owner, and each target retains its independent numerical currents.

Both factories share one actual-column assembler. The reusable support proof keeps dependency-canonical tensors, complete typed ports, absolute orders and formal factors/masks as separate exact fields, with Born, bare, UV, R2 and field domains kept distinct.
